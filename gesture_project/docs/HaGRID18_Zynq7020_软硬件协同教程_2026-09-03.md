## 1. 项目全景与端到端数据流

### 1.1 系统目标

在 Zynq-7020 上，用 PL 加速 18 类静态手势识别 CNN。当前主线是：

```text
96×96×3 RGB
  → conv0: 4×4 SAME, 3→16
  → pool1: 2×2 maxpool
  → conv2a: 4×4 SAME, 16→32
  → conv2b: 4×4 SAME, 32→32
  → pool2: 2×2 maxpool
  → conv3a: 4×4 SAME, 32→48
  → conv3b: 4×4 SAME, 48→48
  → pool3: 2×2 maxpool
  → head: 1×1, 48→64
  → GAP: 全局平均池化
  → FC: 64→18, softmax
```

当前稳定版实测：

- 时钟：80 MHz。
- 端到端：约 41.9 FPS。
- `FINAL_RESULT=0x600D600D`。
- `WNS=+0.365ns`，`WHS=+0.022ns`。
- 资源：DSP 139、LUT 32879、FF 50566、RAMB36 95、RAMB18 7。

### 1.2 Zynq-7020 的硬件背景

Zynq-7020 是 XC7Z020CLG400-2，同时包含 PS 和 PL：

- **PS**：双核 ARM Cortex-A9，跑 baremetal C 程序。
- **PL**：可编程逻辑，资源包括 LUT、FF、BRAM、DSP48E1。
- **AXI**：PS 与 PL 之间的总线。

我们主要用两类 AXI：

- AXI-Lite：低带宽、寄存器读写，用于 PS 控制 PL。
- AXI4 HP0：高带宽，PL 主动访问 DDR，读输入/权重、写输出。

### 1.3 一帧数据真正怎么流动

以第一层为例：

1. PS 把 96×96×3 测试图放在 DDR 某地址。
2. PS 通过 AXI-Lite 写 `DMA_SOURCE`、`DMA_BYTES`、`DMA_PIXELS`。
3. PS 写 `CONTROL=2` 启动。
4. PL 的 RGB loader 通过 HP0 从 DDR 读像素。
5. 行缓存/滑窗把流式像素拼成 4×4 卷积窗口。
6. DMP MAC 读权重 bank，做 INT8 乘加和 INT32 累加。
7. requant 把 INT32 变成 INT8，并融合 ReLU。
8. output bank 暂存，writer 通过 HP0 写回 DDR。
9. PS 轮询 `done`，然后启动下一层。

后面每层都是这个“DDR→片上流式计算→DDR”的循环。最终 head 输出交给 GAP/FC，
不再写回中间 DDR，而是直接得到类别。

### 1.4 为什么是软硬件协同，而不是纯软件或纯硬件

- 纯 PS 软件：CNN 乘加太多，ARM 串行执行不够快。
- 纯 PL 静态电路：不灵活，不同网络、不同层、不同参数都要重新综合。
- 协同设计：PS 做“任务编排和参数配置”，PL 做“固定计算数据通路”。

这带来一个核心约束：算法结构必须和 PL 硬件资源对齐，例如输出通道取 16 的倍数，
卷积核支持 4×4/3×3/1×1，量化用 INT8。

## 3. 算法与训练：18 类学生模型怎么炼成

### 3.1 HaGRID 数据与划分

HaGRID-v1 是手势识别数据集。当前主线使用 384p 目标手部版本，共 18 类。数据准备
脚本在 [`datasets/tools/`](../datasets/tools/)，重点是**按受试者划分** train/val/test，
而不是按图片随机划分。

为什么必须按受试者划分？因为视频里同一个人的相邻帧高度相似。如果随机划分，同一
人的相似帧会同时进入训练集和测试集，测试准确率会虚高，无法反映“对陌生人的手势”
泛化能力。

### 3.2 教师模型：MobileNetV3Large

教师模型只用于训练学生，不上板。入口
[`run_train_hagrid18_teacher.sh`](../algorithms/scripts/run_train_hagrid18_teacher.sh)：

```bash
--arch keras_mobilenet_v3_large
--weights imagenet
--freeze_backbone
--finetune_epochs 20
--label_smoothing 0.05
--mixup_alpha 0.1
```

设计原因：

- MobileNetV3Large 精度高，适合当教师；
- ImageNet 预训练让低层卷积核已经学会边缘、纹理、形状；
- 先冻结 backbone 训练新分类头，避免预训练权重被早期大梯度破坏；
- 再全 backbone 微调，让特征适应手势。

### 3.3 标签平滑

普通 one-hot 交叉熵会让模型把正确类推到 1、其他类推到 0。标签平滑把概率稍微分
给错误类：

```text
correct = 1 - epsilon
others  = epsilon / (K - 1)
```

本项目 `epsilon=0.05`。代码在
[`train_static_cnn.py`](../algorithms/static_cnn/train_static_cnn.py#L285) 的
`build_loss()`。

为什么对量化友好？过尖的输出分布会在 INT8 量化时更容易因为舍入而改变 argmax。
平滑后模型对小幅量化误差更不敏感。

### 3.4 MixUp

MixUp 把两张图线性混合：

```text
x = λ x_a + (1-λ) x_b
y = λ y_a + (1-λ) y_b
```

它让模型在“输入插值”和“标签插值”之间建立平滑映射，属于数据增强 + 正则化。代码
在 [`train_static_cnn.py`](../algorithms/static_cnn/train_static_cnn.py#L474)。

### 3.5 知识蒸馏

知识蒸馏的核心不是“把教师网络复制给学生”，而是让学生学习教师的**软概率分布**。
软目标：

```text
q_i = softmax(log(p_i) / T)
```

温度 `T` 越大，软分布越平滑。学生总损失：

```text
L = (1-α) L_hard + α L_soft
```

本项目 `T=3.0`、`α=0.35`。代码在
[`train_static_cnn.py`](../algorithms/static_cnn/train_static_cnn.py#L344) 的
`build_distillation_trainer()`。

注意：蒸馏 wrapper 只用于训练，导出的是 `student`，所以部署模型不会多出教师分支。

### 3.6 学生结构为什么是 4×4 / 16-32-48 / 1×1 head

这是算法和硬件的联合决策，不是随便选：

- PL 卷积 tile 一次输出 16 通道，所以通道选 16/32/48 能让每个 tile 不浪费。
- DMP MAC 支持 4×4 和 1×1，当前主干用 4×4。
- 最后一层用 1×1 把 48 通道升到 64，再用 GAP 压掉空间维度，最后 FC 分类。
- 1×1 卷积在硬件上复用同一个 DMP 阵列，只是把 `pointwise_mode` 打开。

模型构建入口在
[`train_static_cnn.py`](../algorithms/static_cnn/train_static_cnn.py#L917) 的
`build_model()`。

## 4. 量化、权重打包与 TFLite→硬件接口

### 4.1 INT8 量化的数学

TFLite 量化把浮点值 `r` 表示成：

```text
r = S (q - Z)
```

其中 `S` 是 scale，`Z` 是 zero point，`q` 是 INT8。卷积输出需要重新量化：

```text
q_out = clamp(
    saturating_rounding_doubling_high_mul(acc, multiplier) >> shift
    + Z_out,
    -128, 127)
```

硬件必须逐位复现这个规则。对应模块
[`gestureflow_requant_relu.sv`](../innovation_npu/rtl/gestureflow_requant_relu.sv#L14)。

### 4.2 训练后整型量化

入口 [`quantize_tflite.py`](../algorithms/static_cnn/quantize_tflite.py#L52)：

```python
converter.optimizations = [tf.lite.Optimize.DEFAULT]
converter.representative_dataset = ...
converter.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
converter.inference_input_type = tf.int8
converter.inference_output_type = tf.int8
```

代表数据集从训练集抽 200 张，让 TFLite 统计激活范围，选择每层 scale 和 zero
point。代码在 [`quantize_tflite.py`](../algorithms/static_cnn/quantize_tflite.py#L32)。

### 4.3 DMP 权重为什么按 pair/tap/group 打包

普通卷积权重排布是 `[oc][ic][kh][kw]`。DMP 硬件要同时给一个 DSP 送两个输出通道：

```text
packed[pair][tap][group][word]
pair = oc / 2
tap  = kernel位置
group = ic / 8
word  = 6 个 32-bit 字，组成 192-bit 权重
```

192 bit = 8 输入 lane × 24 bit，每个 lane 的 24 bit 又包含两个输出通道权重：

```text
bits[15:0] = 偶数输出通道权重偏移
bits[23:16] = 奇数输出通道权重偏移
```

为什么 16 bit 而不是 8 bit？因为每个无符号 8×8 乘积最大是 `0xFE01`，需要 16 bit
才能不溢出到另一个乘积。

打包代码在
[`export_dmp_conv_layer.py`](../innovation_npu/tools/export_dmp_conv_layer.py#L69)
和
[`export_dmp_conv_golden.py`](../innovation_npu/tools/export_dmp_conv_golden.py#L114)。

### 4.4 bias 折叠

DMP 把有符号 INT8 偏移成无符号，会多出与输入 zero point、权重 zero point 有关
的修正项。这些常数项被预先加到 bias 里，称为 folded bias。硬件只要在 retire 阶段
再减去 `-128 × sum(a)` 的激活修正项即可。

bias 折叠在
[`export_dmp_conv_layer.py`](../innovation_npu/tools/export_dmp_conv_layer.py#L192)
附近。

### 4.5 为什么要位精确 golden

仿真和实板都通过 FNV 哈希比较整个输出张量。FNV 不是神经网络指标，而是“每个字节
都相同”的快速校验。只要硬件和 TFLite 的量化实现有一点点舍入差异，FNV 就不一样。

## 5. 硬件逐文件精讲

### 5.0 阅读 RTL 的通用方法

读一个 RTL 模块，建议按下面顺序：

1. 先看 `module` 和 `parameter`：这个模块多宽、多深、几个通道。
2. 再看端口：谁是数据流，谁是控制流，谁是 AXI。
3. 再看 `localparam`：内部固定参数，例如 bank 深度、地址宽度。
4. 再看 `typedef enum`：状态机有哪些状态。
5. 再看 `assign`：哪些是组合逻辑，哪些是 ready/valid 握手。
6. 最后看 `always_ff`：每个时钟沿哪些寄存器更新。

不要试图“按行号顺序读”，要按“数据从哪进、在哪算、从哪出”读。

### 5.1 顶层 `gestureflow_layer_chain_dmp_hp0_axil.sv`

#### 5.1.5 HP0 读通道仲裁

- `running`：层正在执行；
- `done`：层完成；
- `fault`：协议/配置错误；
- `hash_active`：正在把输出向量送进 FNV；
- `store_busy/store_done`：writer 状态。

### 5.2 权重 bank：`gestureflow_weight_bank.sv`

文件：
[`gestureflow_weight_bank.sv`](../innovation_npu/rtl/gestureflow_weight_bank.sv#L8)

它是一块双端口 BRAM：

- 一个写口：权重加载；
- 一个读口：卷积时读权重。

为什么要双端口？因为计算和加载不能互相打断。如果只有一个口，权重加载会占住读口，
卷积就得停。

### 5.3 DMP 乘加阵列：`gestureflow_mac_tile_dmp.sv`

文件：
[`gestureflow_mac_tile_dmp.sv`](../innovation_npu/rtl/gestureflow_mac_tile_dmp.sv#L21)

这是本项目最核心的硬件创新点之一。

#### 5.3.1 基本数学

普通 INT8 乘加：

```text
acc_oc += w[oc][ic] × a[ic]
```

DMP 一次同时做两个输出通道：

```text
A = w_even' + (w_odd' << 16)
B = a'
P = A × B = (w_even' × a') + ((w_odd' × a') << 16)
```

这里 `w'` 和 `a'` 是无符号偏移值：

```text
x' = unsigned(x) ^ 0x80
```

也就是把有符号 INT8 从 `[-128,127]` 映射到 `[0,255]`。

#### 5.3.2 为什么 16 bit 间距就够

两个无符号 8 位数相乘，最大是 `255×255=65025=0xFE01`，小于 16 bit 能表示的最大
值 `0xFFFF`。所以低 16 bit 放偶数通道乘积，高 16 bit 放奇数通道乘积，不会互相
污染。

#### 5.3.3 参数

```systemverilog
OUT_LANES = 32  // 默认，但当前板级用 16
INPUT_LANES = 8
MAX_TAPS = 16
MAX_IC_GROUPS = 16
```

其中：

- `PAIR_LANES = OUT_LANES/2`：输出通道对数量；
- `WEIGHT_DEPTH = MAX_TAPS × MAX_IC_GROUPS`：每个 pair 的权重条目数；
- `WEIGHT_DATA_W = INPUT_LANES × 24`：每个条目 192 bit。

#### 5.3.4 权重地址

读地址：

```systemverilog
mac_weight_addr = tap × MAX_IC_GROUPS + ic_group
```

写地址多一位 bank select：

```systemverilog
weight_write_addr = {weight_bank_select,
                     tap × MAX_IC_GROUPS + ic_group}
```

代码在
[`gestureflow_mac_tile_dmp.sv`](../innovation_npu/rtl/gestureflow_mac_tile_dmp.sv#L163)
附近。

#### 5.3.5 多窗口双缓冲

普通单窗口 MAC 在输出结果被 requant 取走前，不能开始下一个窗口，否则累加器会串。
DMP tile 用双缓冲 `accum[0]` 和 `accum[1]`，以及 `windows_active` 计数器，允许
前一个窗口尾部排空时，下一个窗口已经开始填充。

关键信号在
[`gestureflow_mac_tile_dmp.sv`](../innovation_npu/rtl/gestureflow_mac_tile_dmp.sv#L77)
：

```systemverilog
accum[0], accum[1]
activation_sum[0], activation_sum[1]
windows_active
cur_win_id
```

启动条件是：

```systemverilog
start_ready = !s0_valid && !retire_valid && !result_valid
mac_ready = (windows_active != 0) && !retire_valid && !result_valid
```

代码在
[`gestureflow_mac_tile_dmp.sv`](../innovation_npu/rtl/gestureflow_mac_tile_dmp.sv#L205)
附近。

#### 5.3.6 七级流水线

DMP 计算不是一拍完成，而是多级流水：

1. **Stage 0**：锁存激活、权重地址、lane enable；
2. **Stage 1**：同步读权重 BRAM，同时累加激活和；
3. **Stage 2**：DSP 算 25×18 乘积；
4. **Stage 3**：两两相加（pair sum）；
5. **Stage 4**：四个 pair sum 变成 quad sum；
6. **Stage 5**：八路加树完成；
7. **Stage 6**：把 group 结果累加到 `accum`；
8. **Stage 7**：retire 时减激活修正项，输出 INT32 结果。

这些流水寄存器在
[`gestureflow_mac_tile_dmp.sv`](../innovation_npu/rtl/gestureflow_mac_tile_dmp.sv#L285)
附近到
[`gestureflow_mac_tile_dmp.sv`](../innovation_npu/rtl/gestureflow_mac_tile_dmp.sv#L391)
。

为什么要切这么多级？DSP 乘法和 8 路加法如果全组合在一起，关键路径会非常长，80MHz
就收不住。插入寄存器后，每级只做“一次乘法”或“一次两层加法”，路径短。

#### 5.3.7 为什么 retire 要拆成两拍

最早 retire 是：

```text
result = accum + oct_contrib - (activation_sum << 7)
```

这是一个三输入加/减法，在 OUT_LANES 变大时会成为关键路径。后来拆成：

1. Stage 6：`accum += oct_contrib`；
2. Stage 7：`result = accum - (activation_sum << 7)`。

代码在
[`gestureflow_mac_tile_dmp.sv`](../innovation_npu/rtl/gestureflow_mac_tile_dmp.sv#L377)
附近。

### 5.4 卷积流引擎：`gestureflow_conv4x4_cin_same_stream_dmp.sv`

文件：
[`gestureflow_conv4x4_cin_same_stream_dmp.sv`](../innovation_npu/rtl/gestureflow_conv4x4_cin_same_stream_dmp.sv#L14)

#### 5.4.1 职责

它不亲自做乘法，而是做“控制”：

1. 从行缓存/滑窗接收窗口；
2. 存到 `held_window`；
3. 对每个窗口按 `tap` 和 `ic_group` 逐步喂 MAC；
4. 判断 `mac_last`，只有最后一组输入通道/tap 才输出结果。

#### 5.4.2 空间模式与 pointwise 模式

`pointwise_mode` 为 0 时走 4×4 卷积窗口；为 1 时走 1×1，此时 `tile_activation`
直接来自 `held_pixel`，tap 固定为 0。

选择逻辑在
[`gestureflow_conv4x4_cin_same_stream_dmp.sv`](../innovation_npu/rtl/gestureflow_conv4x4_cin_same_stream_dmp.sv#L105)
附近。

#### 5.4.3 窗口握手

```systemverilog
spatial_window_ready = !pointwise_mode && !pending_window && !mac_active;
```

也就是说，只有在“没有等待窗口、MAC 不在算”时才接收新窗口。这是简单的反压
（backpressure），防止 `held_window` 被覆盖。

对应代码
[`gestureflow_conv4x4_cin_same_stream_dmp.sv`](../innovation_npu/rtl/gestureflow_conv4x4_cin_same_stream_dmp.sv#L77)
附近。

#### 5.4.4 遍历顺序

一个 4×4 窗口有 16 个 tap。输入通道每 8 个一组，所以还有多个 `ic_group`。
遍历顺序是：

```text
for tap in 0..15:
  for group in 0..group_count-1:
    MAC(activation[tap][group], weight[tap][group])
```

累加器在窗口内一直保持，直到最后一个 group 才 retire。这个遍历在
[`gestureflow_conv4x4_cin_same_stream_dmp.sv`](../innovation_npu/rtl/gestureflow_conv4x4_cin_same_stream_dmp.sv#L145)
附近。

### 5.5 滑窗与行缓存

#### 5.5.1 `gestureflow_same4x4_cin_window.sv`

文件：
[`gestureflow_same4x4_cin_window.sv`](../innovation_npu/rtl/gestureflow_same4x4_cin_window.sv#L10)

它把像素流转换成完整的 `CHANNELS×16` 窗口。SAME padding 参数在
[`gestureflow_same4x4_cin_window.sv`](../innovation_npu/rtl/gestureflow_same4x4_cin_window.sv#L32)
：

```systemverilog
PADDED_WIDTH = IMAGE_WIDTH + KERNEL_SIZE - 1
PADDED_HEIGHT = IMAGE_HEIGHT + KERNEL_SIZE - 1
PAD_BEFORE = (KERNEL_SIZE - 1) / 2
```

对于 4×4，`PAD_BEFORE=1`。TFLite 的 4×4 SAME padding 并不是完全对称，实际是
top/left 补 1，bottom/right 补 2，硬件必须和 TFLite 一致。

#### 5.5.2 `gestureflow_line_window.sv` 与 vector 版本

文件：

- [`gestureflow_line_window.sv`](../innovation_npu/rtl/gestureflow_line_window.sv#L8)
- [`gestureflow_line_window_vector.sv`](../innovation_npu/rtl/gestureflow_line_window_vector.sv#L7)
- [`gestureflow_line_delay_bank.sv`](../innovation_npu/rtl/gestureflow_line_delay_bank.sv#L7)
- [`gestureflow_line_delay_vector_bank.sv`](../innovation_npu/rtl/gestureflow_line_delay_vector_bank.sv#L7)

“行缓存”不是把整张图都存下来，而是只存足够组成当前窗口的几行。新像素到来时，
旧行数据向右移动，像传送带一样。这样 BRAM 使用量只和行宽、通道数有关，和图像
总行数无关。

### 5.6 requant + ReLU：`gestureflow_requant_relu.sv`

文件：
[`gestureflow_requant_relu.sv`](../innovation_npu/rtl/gestureflow_requant_relu.sv#L14)

#### 5.6.1 为什么不能直接截断

卷积累加器是 INT32，TFLite 的下一层输入是 INT8。直接截断低 8 位是错的，因为量化
scale 不是 2 的整数次幂，必须做乘法 + 舍入 + 右移 + zero point + 饱和。

#### 5.6.2 两级流水化

requant 算术被拆成两段：

1. `product_pipe`：寄存 64-bit 乘积；
2. `shifted_value`：寄存舍入右移后的值；
3. 最后做 zero point 和饱和。

这样 DSP 乘法和后面的移位/加法不在同一个组合路径里。代码在
[`gestureflow_requant_relu.sv`](../innovation_npu/rtl/gestureflow_requant_relu.sv#L350)
附近。

#### 5.6.3 为什么用 4-lane 时间复用

`PARALLEL_LANES=4` 意味着一次只算 4 个输出通道，16 个通道要算 4 次。为什么不做
16 路并行？因为每路都要一个 32×32 乘法和一个可变右移；16 路会让 MUX 和 fanout
都很大，容易成为关键路径。4 路在吞吐足够的情况下，明显减少时序压力。

#### 5.6.4 容易犯的错误

历史记录里出现过“packed 数组变量索引写回导致 -128 饱和错误”。原因是
`out_data[chunk_index*PARALLEL_LANES + lane_off]` 这种变量索引写回在某些综合器/
仿真器下会生成不同的行为。当前代码用固定索引和显式循环，避免这个坑。

### 5.7 DDR 读：RGB loader 与 banked tensor loader

#### 5.7.1 RGB loader

文件：
[`gestureflow_hp0_rgb_loader.sv`](../innovation_npu/rtl/gestureflow_hp0_rgb_loader.sv)

RGB 输入只有 3 通道，但为了和 DMP 8 输入 lane 对齐，硬件把 RGB 当作一个 8 通道
组，高 5 个 lane 用 zero point 填充/屏蔽。

#### 5.7.2 banked tensor loader

文件：
[`gestureflow_hp0_tensor_loader_banked.sv`](../innovation_npu/rtl/gestureflow_hp0_tensor_loader_banked.sv#L10)

中间张量有 16/32/48 通道，不能像 RGB 那样简单。这个 loader 使用 ring buffer：

```systemverilog
typedef enum logic [1:0] {IDLE, ISSUE_AR, RECEIVE_R, DRAIN} state_t;
```

状态机在
[`gestureflow_hp0_tensor_loader_banked.sv`](../innovation_npu/rtl/gestureflow_hp0_tensor_loader_banked.sv#L50)
。

关键设计：

- AXI 一次返回 64 bit，8 字节；
- 16 通道 = 2 个 beats，凑齐 2 个 beats 才能发出一个像素向量；
- ring buffer 用指针取数，不做“把整个寄存器组右移”的大组合逻辑。

`pixel_valid` 在
[`gestureflow_hp0_tensor_loader_banked.sv`](../innovation_npu/rtl/gestureflow_hp0_tensor_loader_banked.sv#L105)

```systemverilog
pixel_valid = (state != IDLE) && stream_started &&
              (buffered_beats >= VECTOR_BEATS)
```

这保证一个像素向量的所有字节都齐了，才交给下游。

### 5.8 DDR 写：`gestureflow_hp0_tensor_writer.sv`

文件：
[`gestureflow_hp0_tensor_writer.sv`](../innovation_npu/rtl/gestureflow_hp0_tensor_writer.sv#L8)

状态机：

```systemverilog
IDLE, ISSUE_READ, CAPTURE_READ, ISSUE_AW, SEND_W, WAIT_B
```

代码在
[`gestureflow_hp0_tensor_writer.sv`](../innovation_npu/rtl/gestureflow_hp0_tensor_writer.sv#L59)
。

写回流程：

1. 从 output bank 读一个或多个向量；
2. 发 AXI AW；
3. 发 W 数据；
4. 等 B response；
5. 重复直到 `vector_count` 写完。

重要设计：

- 普通卷积层可以 `contiguous_burst`，把多个向量合成一个 burst；
- 2×2 池化层从 bank 读 4 个源向量，取 max 后再写一个目标向量；
- `WSTRB` 处理尾 tile 的有效字节；
- `destination_stride_bytes` 让 16 通道 tile 能写进更宽的 NHWC 张量。

### 5.11 GAP + FC：`gestureflow_hp0_gap_fc.sv`

文件：
[`gestureflow_hp0_gap_fc.sv`](../innovation_npu/rtl/gestureflow_hp0_gap_fc.sv#L11)

它读 head 输出的 12×12×64 张量：

1. 对每个通道做 144 元素求和，得到 64 维向量；
2. 对 18 类做 FC 点积；
3. argmax 得到类别。

argmax 不是串行比较 18 次，而是用树形比较器，代码在
[`gestureflow_hp0_gap_fc.sv`](../innovation_npu/rtl/gestureflow_hp0_gap_fc.sv#L113)
附近。

### 5.12 当前硬件资源与时序怎么理解

资源报告里的 DSP 139 不只来自 DMP MAC。它还包括：

- DMP MAC 64 个 DSP；
- requant 4-lane 的乘法器；
- GAP/FC 的乘加；
- FNV 和其他定点运算。

因此看到 DSP 增加不要只看 MAC。BRAM 95+7 主要来自：

- 权重 bank；
- output bank；
- 行缓存。

时序关键路径通常来自：

- DMP 乘积到加树；
- requant 的高扇出 multiplier/right_shift；
- AXI-Lite 配置寄存器 fanout；
- SmartConnect 的读命令 FIFO。

当前 XDC 只对 `layer_mode_reg` 设置 false path，因为它在层执行期间是准静态的。
文件：
[`gestureflow_hagrid18_dmp_7020_timing.xdc`](../innovation_npu/board_7020/gestureflow_hagrid18_dmp_7020_timing.xdc)

## 6. PS 软件逐函数精讲

文件：
[`gestureflow_hagrid18_dmp_main.c`](../innovation_npu/board_7020/software/gestureflow_hagrid18_dmp_main.c)

### 6.1 头部宏与地址

```c
#define GF_BASE 0x43C00000U
#define PROBE_BASE 0xFFFF0000U
```

`GF_BASE` 是 AXI-Lite 寄存器基地址，和 Block Design 地址分配一致。
`PROBE_BASE` 是 PL 里一块可直接读写的寄存器数组，PS 把性能数据写进去，XSCT 再读。

地址定义从
[`gestureflow_hagrid18_dmp_main.c`](../innovation_npu/board_7020/software/gestureflow_hagrid18_dmp_main.c#L44)
开始。

### 6.2 内存属性与 Cache

```c
Xil_SetTlbAttributes(GF_BASE, DEVICE_MEMORY);
Xil_SetTlbAttributes(PROBE_BASE, DEVICE_MEMORY);
```

外设寄存器不能用普通 cacheable memory，否则 ARM 可能把写操作缓存起来，导致 PL
看不到控制字。设为 `DEVICE_MEMORY` 后，访问是强顺序的。

### 6.3 失败处理

`terminal_failure(code, observed)` 会把 `code` 写到 `PROBE[2]`，把 `observed`
写到 `PROBE[3]`，然后把 `PROBE[0]` 写成 `0xBAD0BAD0`。XSCT 看到这个值就知道失败，
并继续读诊断寄存器。

代码：
[`gestureflow_hagrid18_dmp_main.c`](../innovation_npu/board_7020/software/gestureflow_hagrid18_dmp_main.c#L184)

### 6.4 等待层完成

```c
if ((status & GF_DONE_BIT) && !(status & GF_RUNNING_BIT)) return;
```

必须同时看 done 和 !running。只等 done 会在 `done` 和 `running` 同拍变化时出现
竞态。代码在
[`gestureflow_hagrid18_dmp_main.c`](../innovation_npu/board_7020/software/gestureflow_hagrid18_dmp_main.c#L203)
。

### 6.5 权重 DMA 装载

`weight_dma_load()` 做四件事：

```c
Xil_Out32(WEIGHT_DMA_SOURCE, src);
Xil_Out32(WEIGHT_DMA_BYTES, bytes);
Xil_Out32(WEIGHT_DMA_CFG, taps | (groups << 8) | (output_lanes << 16));
Xil_Out32(WEIGHT_DMA_CONTROL, 2);
```

它不逐字写权重，而是告诉 PL“从 DDR 哪个地址读多少权重”。PL 自己发 HP0 读请求。
代码在
[`gestureflow_hagrid18_dmp_main.c`](../innovation_npu/board_7020/software/gestureflow_hagrid18_dmp_main.c#L217)
。

### 6.6 bias / requant 配置

`config_tile_params()` 对每个物理输出通道写：

```c
BIDX/BDATA    → folded bias
RQIDX/RQMULT  → requant multiplier
RQIDX/RQSHIFT → right shift
```

代码在
[`gestureflow_hagrid18_dmp_main.c`](../innovation_npu/board_7020/software/gestureflow_hagrid18_dmp_main.c#L331)
。

为什么 bias 不是训练时的原始 bias？因为 DMP 的偏移修正被预折叠进 bias，所以软件
直接写导出的 `folded_bias`。

### 6.7 启动一层

`launch_layer()` 在
[`gestureflow_hagrid18_dmp_main.c`](../innovation_npu/board_7020/software/gestureflow_hagrid18_dmp_main.c#L373)
：

```c
LAYER_MODE, DMA_SOURCE, DMA_BYTES, DMA_PIXELS,
JOB_WIDTH, JOB_HEIGHT,
STORE_DESTINATION, STORE_BYTES, STORE_STRIDE, STORE_VALID_BYTES,
STORE_CONTROL, CONTROL=2
```

这些寄存器必须在 `CONTROL=2` 之前写完，硬件在 CONTROL 沿锁存任务。

### 6.8 一个 tile 的完整执行

`exec_conv_tile()` 在
[`gestureflow_hagrid18_dmp_main.c`](../innovation_npu/board_7020/software/gestureflow_hagrid18_dmp_main.c#L425)
：

1. `CONTROL=1` 复位；
2. 选 bank；
3. 写 layer mode/QCFG/lane mask；
4. 预载权重；
5. 写 bias/requant；
6. `launch_layer()`；
7. `wait_layer_done()`；
8. 读 `GF_CYCLES`。

### 6.9 整网调度

`main()` 从
[`gestureflow_hagrid18_dmp_main.c`](../innovation_npu/board_7020/software/gestureflow_hagrid18_dmp_main.c#L535)
开始。它按顺序调用：

```text
conv0
conv1+pool1
conv2a tile0/tile1
conv2b+pool2 tile0/tile1
conv3a tile0/tile1/tile2
conv3b+pool3 tile0/tile1/tile2
head1x1 tile0..tile3
GAP+FC
```

每层结束都会做：

- `check_input_bytes()`；
- `check_store_bytes()`；
- 读 `OUTPUT_FNV1A` 与 golden 比较。

### 6.10 为什么 16 输出通道 tile 要切多块

conv2a 输出 32 通道，但物理 tile 是 16 通道，所以切 2 块；conv3a 输出 48 通道，
切 3 块；head 输出 64 通道，切 4 块。每块写回不同 `first_oc` 偏移，软件传
`destination + first_oc`。

### 6.11 性能探针

软件把以下数据写入 PROBE：

- `PROBE[130]`：整帧 ticks；
- `PROBE[131]/[132]`：权重相关 ticks；
- `PROBE[133]`：PL 总 cycles；
- `PROBE[10..26]`：逐层 cycles。

写入位置在
[`gestureflow_hagrid18_dmp_main.c`](../innovation_npu/board_7020/software/gestureflow_hagrid18_dmp_main.c#L696)
附近。

### 6.12 当前软件的一个已知可优化点

当前软件是同步调度：先等一层完全结束，再装载下一层权重。硬件其实支持双 bank
ping-pong，可以在当前层写回 DDR 时预载下一层权重。这个优化还没稳定接入主线，
是下一步重点。

## 8. 项目接管开发指南

### 8.1 改动风险分级

1. **只改 PS 软件**：风险低，必须重新编译 ELF + 实板验证。
2. **改 RTL 数值路径**：风险高，必须先 Verilator。
3. **改架构/资源/时序**：风险最高，先做纸面资源估计，不要反复空跑综合。

### 8.2 换模型

步骤：

1. 训练新 `.keras`；
2. 用 `quantize_tflite.py` 出 INT8 TFLite；
3. 用 `export_hagrid18_all_layers_dmp.sh` 重新导出权重头；
4. 更新 `gestureflow_hagrid18_dmp_main.c` 里的层参数/golden；
5. Verilator；
6. Vivado；
7. 上板。

### 8.3 换数据集

数据集脚本在
[`datasets/tools/`](../datasets/tools/)。
保持 subject split，不要随机图片划分。

### 8.4 排查时序

看报告里的 WNS 和最差路径：

- 逻辑级数多 → 插流水寄存器；
- 布线延迟高 → pblock / 重排 / 降低扇出；
- 高扇出控制信号 → 复制寄存器或 `max_fanout`；
- XDC 注释必须用 `#`。

### 8.5 排查板上 fault

先读 `PROBE[2]` 和 `PROBE[3]`，再到 main 里查对应 `terminal_failure` 编号。

常见根因：

- 上一状态未清；
- AR 通道冲突；
- 权重 bank 选错；
- WSTRB/burst 长度错；
- `STORE_STATUS` 误读；
- packed 数组变量索引写回。

### 8.6 判断一次优化是否真的成功

必须四项同时满足：

1. `FINAL_RESULT=0x600D600D`；
2. 所有层 FNV 与 golden 一致；
3. `WNS>0`，且最好有裕量；
4. DSP/BRAM/LUT 在 Zynq-7020 余量内。

只看到 FPS 提高、但 FNV 变了，说明算错；只看到功能对、但时序为负，说明不能
稳定量产；只看到时序对、但资源超了，说明下一版无法扩展。

## 9. 故障检查表

| 现象 | 优先检查 |
|---|---|
| 仿真 FNV 不对 | requant 公式、weight 打包、padding、lane enable |
| 板上 `0x4001` | STATUS fault：CONTROL 启动时仍有 busy/running，或权重 bank 冲突 |
| 板上 `0x4D01` | weight DMA fault：地址/字节数/配置错误 |
| 板上 `0x4D02` | input DMA 没完成 |
| `STORE_STATUS` 字节数不对 | writer 的 vector_count/valid_bytes/stride/pool_2x2 |
| WNS 为负 | 关键路径报告，先定位 DMP 加树还是 requant 还是 AXI |
| BRAM 超限 | 是否误开 `ENABLE_RELAY` 或 output bank 深度过大 |
| DSP 超限 | 是否把 requant 并行度过大，或 OUT_LANES 开 32 |
