# 项目全程阶段总结 阶段1 算法与数据集探索

## 1. 阶段定位

这一阶段对应项目从立项到“正式静态算法主线收敛”之前的全部工作，核心目标不是立刻改硬件，而是先把下面这条事实链跑通：

```text
方向设想 -> 数据集准备 -> 候选模型比较 -> 真实训练 -> INT8 量化 -> TFLite/周期画像 -> 主线收敛
```

这一阶段结束后，项目已经不再停留在“大创计划书里的设想”，而是形成了一个能支撑后续软件优化与硬件对接的正式模型主线。

## 2. 数据集与任务口径

当前正式静态任务口径是：

- 数据集：`gesture_project/datasets/processed/hagrid_sample_static_6cls`
- 类别：`fist`、`like`、`ok`、`palm`、`peace`、`stop`
- 输入尺寸：主线采用 `96x96`
- 任务类型：静态手势分类

这一步的关键不是“数据集足够大”，而是先建立一个可重复、可量化、能服务后续 NPU 周期分析的统一任务口径。

相关材料：

- `gesture_project/docs/HaGRID下载与子集整理.md`
- `gesture_project/docs/数据集调研与执行计划.md`

这一阶段已经建立起完整的软件侧工具链，后续任何新增算法都应复用它，而不是再各自手写一套流程。


## 4. 当前已经验证过的代表性模型

### 4.1 正式静态主线

- 模型：`static_cnn_regularized_3x3_i96_e70_hagrid6_sample`
- Keras 测试精度：`77.29%`
- INT8 TFLite 测试精度：`77.07%`
- 量化损失：`0.22 pct`
- 模型级估算 reference / optimized cycles：
  `1,130,091,474 / 63,313,051`
- 模型级估算加速：`17.85x`

它之所以成为正式主线，不是因为“我们偏爱 3x3”，而是因为它同时满足：

- 精度明显优于本阶段其它正式对照
- INT8 量化后几乎不掉点
- 热点高度集中在 `3x3 Conv2D`
- 与 CoralNPU 当前优化收益方向一致

- `gesture_project/reports/static_cnn_regularized_3x3_i96_e70_hagrid6_sample_tflite_eval.json`

### 4.2 正式轻量对照

- 模型：`mobilenet_v2_a050_96_imagenet_frozen_finetune_hagrid6_sample`
- Keras / INT8：`59.73% / 58.40%`
- 模型级估算加速：`2.62x`
- 主导瓶颈：`1x1 pointwise Conv2D`

这条线的价值不在于打败当前主线，而在于让我们确认：

- `depthwise` 不是当前 CoralNPU 路径的主要短板
- 真正拖慢 MobileNet 类模型的是大量 `1x1 pointwise`
- 未来若要扩 RTL 覆盖面，`1x1 pointwise` 才是正式次级方向

### 4.3 已真实训练否定的结构线

当前已经可以明确归档为“首轮真实训练失败样本”的两条结构线：

- `repvgg_3x3`
- `residual_3x3`

不是说论文路线永远无价值，而是：

```text
在当前工作区这版实现、当前 HaGRID 6 类静态任务和当前训练口径下，
它们没有表现出进入正式第二层算法候选的价值。
```

对应总结：

## 5. 这一阶段形成的正式结论

### 5.1 算法主线已经收敛

当前正式算法主线是：

```text
static_cnn_regularized_3x3_i96_e70_hagrid6_sample
```

这条线后续仍然是：

- 软件优化对账基线
- official replay 主体 workload 来源
- 上板展示时最稳的静态手势算法保底线

### 5.2 当前不能再回到“只看精度”或“只看结构名”

后续新增算法必须经过同一条闭环：

```text
真实训练 -> INT8 量化 -> TFLite 评估 -> 算子画像 -> NPU 周期画像 -> 是否值得继续
```

### 5.3 动态手势值得做，但不能默认先做 LSTM

结合计划书重审与当前算法事实，后续更合理的并行候选应是：

- `landmark + MLP/GRU/TCN` 轻时序对照
- 更贴近 plain-conv 的结构对照

而不是把 `LSTM` 直接当成近期硬件主线。

## 6. 本阶段踩过的坑

### 6.1 不要把 PDF 或“研究现状”直接当技术结论

计划书和外部研究只能提供方向感，不能替代当前工作区的真实训练和回放结果。

### 6.2 不要只看参数量或静态 MAC

MobileNet 类模型虽然 MAC 低，但如果优化后周期几乎都落在 `1x1 pointwise` 上，模型级收益仍然可能明显低于 3x3-heavy 主线。

### 6.3 不要为了新结构反复烧长训练预算

如果一条结构线前几轮就长期卡在随机猜测附近，应尽快止损归档，不要占用主线资源。

## 7. 本阶段对后续的直接影响

这一阶段已经为后续几件事提供了确定前提：

- 后续 official 软件优化应优先服务 `3x3` 主体层
- `1x1 pointwise` 只作为未来第二优先扩展方向
- 板级/硬件侧必须围绕当前正式静态主线来做可验证闭环

## 8. 后续正确接法

从当前阶段续接，正确做法不是再回头重开一轮大规模候选扫描，而是：

1. 固定 `static_cnn_regularized_3x3_i96_e70_hagrid6_sample` 为正式算法保底线。
2. 软件/official replay 继续围绕其四个主体层收敛 current best。
3. 板级第二层只做最小可验证硬件参考语义，不再让算法主线漂移。
