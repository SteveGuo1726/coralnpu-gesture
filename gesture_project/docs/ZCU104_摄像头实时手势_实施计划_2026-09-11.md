## 0. 先决结论：为什么必须上 Linux

USB 摄像头需要 **USB Host 模式 + UVC 类驱动**。AMD 官方文档（ZynqMP USB Standalone Driver）
在 *Known Issues and Limitations* 里明确写着：

> **Host mode is not supported by the standalone driver**

裸机 `usbpsu` 只有 **Device 模式**。所以「裸机直接读 USB 摄像头」这条路**不存在**，
必须跑 Linux（`dwc3` + `xhci-hcd` + `uvcvideo`）。

**已确认的硬件前提**（来自 ZCU104 板卡预设，我们的 BD 已应用）：

| 项 | 值 |
|---|---|
| `PSU__USB0__PERIPHERAL__ENABLE` | 1 |
| `PSU__USB0__PERIPHERAL__IO` | MIO 52..63（USB2.0） |
| `PSU__USB3_0__PERIPHERAL__ENABLE` | 1 |
| `PSU__USB3_0__PERIPHERAL__IO` | **GT Lane2**（USB3.0，走 PS-GTR） |
| `PSU__USB0__REF_CLK_SEL` | Ref Clk2 @ 26 MHz |

→ PS 侧 USB3 已经在我们的设计里配好了，Linux 只需 `dr_mode = "host"` + 打开 UVC。

`0x600D600D` = "GOOD GOOD"。完整 18 层 HaGRID-18 网络在 ZCU104 上跑通，
`PROBE[10]..[26]` 非零说明各层的 FNV 校验都实际执行了。

### 实测性能

| 项 | 值 | 说明 |
|---|---|---|
| **整帧** | 2,705,924 ticks @100MHz = **27.06 ms → 36.96 FPS** | `PROBE[130]` |
| **PL 计算** | 1,702,205 cycles @100MHz = **17.02 ms** | `PROBE[133]` / `GF_CYCLES` |
| **CPU 侧开销** | **10.04 ms（占 37%）** | 整帧 − PL |
| 权重装载 | 0.49 ms | `PROBE[131]` |
| 7020 基线 | 23.81 ms（42 FPS） | 参考 |

**两个明确结论**：

1. **PL 本身比 7020 快**（17.02 ms @100 MHz；7020 在 80 MHz 下约 21.3 ms）。
2. **CPU 侧 10 ms 是当前最大瓶颈**。根因高度指向 `main.c` 里的
   `Xil_SetTlbAttributes(<buf>, DEVICE_MEMORY)` —— 它把全部工作缓冲设成 **Device 内存**
   （非缓存 + 强序），A53 每次访问都走最慢路径。
   → 改成 **Normal cacheable + 精确 flush/invalidate** 是下一步最大的性能杠杆。
3. 若 PL 提到 137 MHz（时序余量允许）：PL → 12.42 ms，整帧 → 22.4 ms → **44.5 FPS**。

### 上板踩到的三个坑（已修复）

| 坑 | 现象 | 修法 |
|---|---|---|
| **APU L2 被按在复位** | `dow` 报 `APU L2 cache is held in reset` | `psu_init` → **`rst -processor -clear-registers`** → `dow`。**Zynq-7000 无此步**，所以 7020 流程不需要 |
| **AArch64 无 data/prefetch abort 异常 ID** | 编译报 `XIL_EXCEPTION_ID_DATA_ABORT_INT undeclared` | 用 `XIL_EXCEPTION_ID_SYNC_INT` + `SERROR_ABORT_INT`，加 `#if defined(__aarch64__)` 保护（7020 不受影响） |
| **`app build` 在 xsct 里挂起** | 无输出、无进程、无报错 | 改用 7020 的做法：直接 `aarch64-none-elf-gcc` 编译 + `app create` 生成的 `lscript.ld`（aarch64 不需要 `Xilinx.spec`） |

#### ⚠️ locale 是硬性要求（不是可选优化）

本机只有 `C.UTF-8`，而 PetaLinux 在两处**硬编码** `LC_ALL="en_US.UTF-8"`
（`tools/xsct/bin/rdiArgs.sh:37` 等）。这会连锁引发两个**致命**故障：

1. **`gen-machineconf` 直接 core dump** —— XSCT 的 C++ 工具抛
   `locale::facet::_S_create_c_locale name not valid` → `Aborted` → 工程配置失败。
2. **BitBake 误判 gcc 版本** —— `/bin/sh` 的 setlocale 警告被写进 stderr，
   而 BitBake 用 `stderr=STDOUT` 合并后**只解析第一行**（`poky/meta/lib/oe/utils.py:430`）：
   ```python
   match = re.match(r".* (\d+\.\d+)\.\d+.*", output.split('\n')[0])
   if not match: bb.fatal("Can't get compiler version from gcc --version output")
   ```
   → 匹配到的是警告文本 → `bb.fatal` → 构建秒退。

实测对照（`/bin/sh -c 'gcc  --version'`，合并 stderr，取第一行）：

| 环境 | 第一行 | 结果 |
|---|---|---|
| 无 locale 变量 | `gcc (Ubuntu 11.4.0...) 11.4.0` | OK |
| 仅 `LOCPATH` | `gcc (Ubuntu 11.4.0...) 11.4.0` | OK |
| `LOCPATH` + `LC_ALL=en_US.UTF-8` | `gcc (Ubuntu 11.4.0...) 11.4.0` | OK |
| **仅 `LC_ALL=en_US.UTF-8`（无 LOCPATH）** | **`/bin/sh: warning: setlocale: ...`** | **FAIL** |
| `LC_ALL=C.UTF-8` | `gcc (Ubuntu 11.4.0...) 11.4.0` | OK |

→ **必须系统级生成 `en_US.UTF-8`。**

### 3.4 为什么 USB3 摄像头**不用**手改设备树

设了 `MACHINE_NAME = zcu104-revc` 之后，PetaLinux 会引入官方板级 DTS
`arch/arm64/boot/dts/xilinx/zynqmp-zcu104-revC.dts`，其中 USB 已经是这样：

```dts
/* ULPI SMSC USB3320 */
&usb0 {
	status = "okay";
	pinctrl-names = "default";
	pinctrl-0 = <&pinctrl_usb0_default>;
	phy-names = "usb3-phy";
	phys = <&psgtr 2 PHY_TYPE_USB3 0 2>;    /* GTR Lane2, 与板卡预设一致 */
};

&dwc3_0 {
	status = "okay";
	dr_mode = "host";                       /* 官方默认就是 Host */
	snps,usb3_lpm_capable;
	maximum-speed = "super-speed";
};
```

**`dr_mode = "host"` 和 `maximum-speed = "super-speed"` 官方已经写好了**，
且 `psgtr 2 PHY_TYPE_USB3` 与 ZCU104 板卡预设的 `PSU__USB3_0__PERIPHERAL__IO = GT Lane2`
**完全对得上**。所以 USB3 Host **不需要任何手工 patch** —— 这正是走 ZCU104 原生流程
而不是套 7020 流程带来的收益。

> 顺便：官方板级 DTS 还带了 **128 MB CMA**（`linux,cma`, 128 MB 对齐, 0–2 GB 范围），
> 这对后面给 NPU 分配**物理连续**缓冲很有用。

## 4. P3：SD 卡与启动

### 4.1 SD 卡分区（PetaLinux SD-boot 标准布局）

```
分区1  FAT32, ~1 GB   : BOOT.BIN, image.ub, boot.scr, system.dtb
分区2  ext4,  剩余     : rootfs.ext4 直接写入（选了 EXT4 才有这个文件）
```

### 4.2 ZCU104 启动模式开关 SW6

**来源：UG1267 Table 2-4 + AMD Adaptive Computing Wiki「Boot Modes」**（两者一致）

| Boot Mode | Mode Pins [3:0] | **SW6 [4:1]** |
|---|---|---|
| JTAG | 0000 | ON, ON, ON, ON |
| QSPI32 | 0010 | ON, ON, OFF, ON ← **出厂默认** |
| **SD1** | **1110** | **OFF, OFF, OFF, ON** |

**极性要注意**（UG1267）：`ON = 拉低 = 0`，`OFF = 上拉 = 1`。
所以 SD1 是 **SW6-4/3/2 = OFF，SW6-1 = ON**。

→ 跑 Linux 时拨成 **SD1**；做 P1 裸机验证（JTAG 下载）时保持 JTAG 或 QSPI 都能连。

### 4.3 串口

ZCU104 的 USB-UART 走 FT4232H，**channel 0 = MPSoC UART0**，**115200 8N1**。
板级 DTS 里 `stdout-path = "serial0:115200n8"` 与之一致。

> ZCU104 套件**自带一张预装 PetaLinux 参考设计的 SD 卡**。建议留作备用，另用一张卡做本项目。

## 5. P4：用户态 NPU 访问（技术要点，先记下）

### 5.1 寄存器
`0xA0000000` 处的 AXI-Lite 控制口，Linux 下用 `/dev/mem` + `mmap` 访问。
PL 区不属于 System RAM，通常不受 `CONFIG_STRICT_DEVMEM` 限制，但要实测确认。

### 5.2 ⚠️ 关键风险：HP0 是非相干端口

我们的 NPU 走 **`S_AXI_HP0_FPD`（非相干）** 读写 DDR。A53 有 D-Cache，所以：

- NPU 读之前：CPU 必须 **flush** 输入缓冲
- NPU 写之后：CPU 必须 **invalidate** 输出缓冲

Linux 用户态**不能**直接发 `dc civac`。可行方案（按落地难度排序）：

1. **让缓冲区对 CPU 是 non-cacheable** —— 用一个极小的字符设备/UIO 驱动，把预留物理区
   以 `pgprot_noncached` 映射给用户态。UIO 的通用 mmap 本身就是 non-cached，
   `uio_pdrv_genirq` + DT 节点即可。**推荐**。
2. `u-dma-buf`（`ikwzm/udmabuf`）—— 现成的连续 DMA 缓冲 + cache sync ioctl，但需针对
   PetaLinux 内核编译模块。
3. `dma_alloc_coherent` 的自定义驱动 —— 最正统，但要自己写平台驱动。

设计上：**DT 里预留一段 DDR**（`reserved-memory`），用户态 mmap 成 non-cacheable，
NPU 与 CPU 各自读写同一段，省掉所有 cache 操作。

### 5.3 帧格式转换

摄像头（UVC）通常给 **YUYV** 或 **MJPEG**。模型输入是 RGB 定尺寸。需要：
- MJPEG → JPEG 解码（V4L2 支持 MJPEG 直出，用 `libjpeg` 或让摄像头出 YUYV）
- YUYV → RGB888 → 缩放到模型输入尺寸 → 量化成 INT8 → 写入 NPU 输入缓冲

**建议先让摄像头出 YUYV**（免解码，帧率够用），链路最短。

## 6. 风险与备选

| 风险 | 影响 | 应对 |
|---|---|---|
| PetaLinux 在 WSL2 上跑不顺 | 构建失败 | WSL2 限制多但可用；必要时在原生 Ubuntu 上建 |
| ~~生成的 DT 里 USB 不是 host 模式~~ | —— | **已排除**：`zcu104-revc` 板级 DTS 里 `dr_mode="host"` 是官方默认（见 3.4） |
| HP0 非相干导致数据错 | 结果不对 | 用 non-cacheable 映射（见 5.2） |
| UVC 摄像头在 USB3 上枚举成 USB2 | 带宽/帧率下降 | 先跑通再说，后续调 GTR/USB3 链路 |
| PetaLinux 构建耗时数小时 | 进度慢 | 先只 build 内核 + rootfs 验证 USB，再补全 |
| 首次构建要联网下 Yocto 源码 | 网络不稳会失败 | 必要时下 sstate-cache / Yocto Downloads 镜像 |

**备选（若 PetaLinux 受阻）**：用预编译 ZCU104 Linux 镜像 + `bootgen` 以我们 XSA 的
`psu_init` 自建 `BOOT.BIN`。快很多，但要实测 HP0 从口是否被正确初始化（stock 镜像的
`psu_init` 不一定开 AFI）。
