# 手势识别算法选择与未来硬件协同方案 2026-07-30

## 1. 这份文档解决什么问题

这份文档回答的是：

```text
当前项目后续应该选什么算法主线，
以及这些算法要怎样和未来的 CoralNPU 适配硬件方案一起规划。
```

重点不是回顾旧阶段，而是给出当前最稳、最强、最值得继续执行的路线。

## 2. 当前已知事实

### 2.1 纯卷积保底线仍然成立

当前项目已经保留下来的纯图像卷积保底线是：

- 模型目录：
  - `gesture_project/models/static_cnn_regularized_3x3_i96_e70_hagrid6_sample_wsl_retrain_20260707`
- 结果文件：
  - `gesture_project/reports/static_cnn_regularized_3x3_i96_e70_hagrid6_sample_wsl_retrain_20260707_keras_eval_20260728.json`

当前测试准确率：

- `79.24%`

它的价值不是“当前整体算法最优”，而是：

- 结构简单
- 量化稳定
- 与后续纯卷积硬件映射最直接

### 2.2 当前整体静态最优系统线已经不是单分支 CNN

当前项目内已经保留的关键点和融合结果表明：

- 关键点单模已经明显强于当前纯卷积保底线
- 图像 CNN 与关键点模型的错误模式有明显互补

关键结果：

- `gesture_project/reports/static_cnn_landmark_fusion_20260728.json`
- `gesture_project/reports/static_cnn_landmark_geom_fusion_20260728.json`
- `gesture_project/reports/static_cnn_landmark_geom_fusion_20260728_script.json`

当前最强静态系统结果：

- `val_accuracy = 94.27%`
- `test_accuracy = 94.62%`

因此必须明确分层：

- `纯卷积保底线`
  用于后续卷积硬件映射。
- `当前整体最优静态系统线`
  用于定义精度上限、做教师模型、指导动态路线。

2026-07-31 额外补充：

- 新训练出的 `RepVGG` 图像分支单模型已经把静态图像线推到约 `89.47%` 的测试推理准确率。
- 继续把这个分支和当前关键点 `MLP` 做系统级融合后，测试准确率进一步到 `94.62%`。
- 这说明后续静态主线不能只盯着单一纯图像网络，还要继续保留“图像分支 + 关键点分支”的系统融合思路。

### 2.3 MobileNet 风格不是当前软件主链下的最优硬件匹配

项目当前保留的对照结果已经说明：

- `MobileNetV2` 在当前路径下主要卡在 `1x1 pointwise`
- 模型级估算加速只有约 `2.62x`

对应文件：

- `gesture_project/reports/mobilenet_v2_a050_96_imagenet_frozen_finetune_hagrid6_sample_keras_eval.json`
- `gesture_project/reports/mobilenet_v2_a050_96_imagenet_frozen_finetune_hagrid6_sample_npucycles.json`
- `gesture_project/reports/mobilenet_v2_a050_96_imagenet_frozen_finetune_hagrid6_sample_hotspots.md`

这说明：

- 不能因为它叫“轻量网络”就默认它最适合当前 CoralNPU 公开软件主链

## 3. 当前正式算法路线建议

## 3.1 静态手势

### A 线：纯卷积保底线

定位：

- 后续空间卷积硬件映射基线

建议继续保留：

- `plain-conv`
- 通道尽量对齐 `16`
- 不引入复杂多分支部署结构

建议用途：

- 作为未来 `3x3 / 4x4` 空间卷积后端的第一硬件映射对象

性能口径必须单独说明：

- 当前这条 `3x3` 模型已有的 `17.85x` 是项目侧周期估算，不是官方模拟器直接实测。
- 官方同一卷积测试中的 `3x3` 回退样例，参考周期为 `818453`，优化周期为 `917016`，实际只有 `0.89x`。
- 因此它现在更适合作为精度与功能保底线，不能直接当成官方硬件性能主线。

### B 线：当前整体最优静态系统线

定位：

- 当前真实最高静态精度路线

组成：

- 图像分支 `CNN`
- 关键点分支 `landmark MLP`
- 晚融合

建议用途：

- 作为教师系统
- 作为错误模式分析上限
- 作为后续蒸馏和动态逐帧底座

### C 线：受控对照线

当前建议新增但要受控推进的对照，不再大面积发散：

1. `4x4-heavy plain-conv`
   目的：利用官方模拟器已经证实的 `4x4` 周期优势，同时继续修复纯 `4x4` 网络的精度问题。
2. `受控 mixed depthwise`
   目的：只少量引入 `3x3 depthwise`，避免再次掉进 `1x1 pointwise` 主导陷阱。

不建议当前继续大规模投入：

- 大量 `1x1 pointwise` 主导骨干
- 重分支部署结构
- 没有真实周期画像支撑的大模型扫描

### D 线：已经实测但不推荐继续硬耗的候选

#### 纯 4x4 卷积候选

当前已经实测的纯 `4x4` 静态候选是：

- 模型目录：
  - `gesture_project/models/static_cnn_regularized_plain_k4_i96_e40_hagrid6_sample_20260730`
- 评测结果：
  - Keras 测试准确率约 `43.07%`
  - INT8 TFLite 测试准确率约 `42.18%`
  - 最佳验证准确率约 `39.38%`

这条线的结论非常明确：

- 它确实对上了官方源码里存在的 `4x4 Conv2D` 优化路径。
- 但它没有达到当前手势任务可用的精度门槛。
- 所以它不能直接替换当前 `3x3` 精度保底线，但也不能简单丢弃，因为官方模拟器已经证明 `4x4` 是当前性能优势路径。
- 后续更值得做的是“保留关键 3x3 表达能力、让主体计算尽量进入 4x4 路径”的精度修复，而不是继续训练一个完全同质的纯 `4x4` 网络。

#### 混合 3,3,4 核候选

当前还试过一条更保守的混合核候选：

- `static_cnn_regularized_plain_k3_4_4_i96_e60_hagrid6_sample_20260730`

它目前只跑到 12 轮，最佳验证精度仍然很低，当前状态不值得继续在这条线上硬耗。

## 3.2 动态手势

当前动态路线不要直接从 `LSTM` 起步。

更合理的优先级是：

1. `landmark sequence + GRU`
2. `landmark sequence + TCN`
3. `逐帧强分类器 + 时间平滑 / 迟滞`

原因：

- 关键点路线在当前项目里已经被真实结果证明有效
- 动态任务先压成关键点序列，系统复杂度更低
- 更容易和未来稠密矩阵后端对应
- 不会过早把硬件路线绑死在 `LSTM` 上

## 4. 与未来硬件协同的正确拆分

### 4.1 空间卷积后端

主要服务：

- `3x3 standard conv`
- `4x4 standard conv`
- 必要的 `3x3 depthwise`

建议能力：

- 行缓冲
- 滑窗复用
- 权重驻留
- 片上部分和累加
- 量化与激活融合

最适合映射：

- 当前纯卷积保底线
- 未来以 `4x4` 为主体、少量保留 `3x3` 的混合空间卷积候选

### 4.2 稠密矩阵后端

主要服务：

- `1x1 pointwise`
- `FC`
- `MLP`
- `GRU gate`
- 融合头

建议能力：

- 小 tile 矩阵乘
- INT8 输入与 INT32 累加
- requant 融合
- 小批量序列推理

最适合映射：

- landmark MLP
- 动态 GRU/TCN 中的稠密层
- 未来融合模块

### 4.3 为什么必须双路线而不是单一路线

因为当前项目已经由真实结果表明：

- 单一纯卷积路线精度不再是系统最优
- 关键点与时序路线的计算形态，与空间卷积并不相同

如果后续硬件只继续朝单一 `3x3` 空间卷积方向收窄，就会和算法最优线越走越远。

## 5. 当前最推荐的执行顺序

### 第一阶段

- 保住当前纯卷积保底线
- 保住当前关键点与融合结果
- 把这两条写成统一评估口径

### 第二阶段

- 继续做 `4x4` 性能主线的精度修复，但不再重复训练已经证明低精度的纯 `4x4`
- 新增 `landmark sequence + GRU`
- 新增 `landmark sequence + TCN`

### 第三阶段

- 对比：
  - 精度
  - INT8 量化稳定性
  - 算子组成
  - 周期估算
  - 与未来双后端硬件的映射难度

### 第四阶段

- 形成最终硬件优先算法组合：
  - 一个空间卷积保底线
  - 一个静态系统最优线
  - 一个动态主线

## 6. 当前禁止再犯的路线错误

- 不再把“当前最优算法”写成单一 `79%` 的纯卷积模型。
- 不再因为旧 `3x3` 局部试验积累多，就默认未来所有硬件都只围绕它展开。
- 不再默认 `LSTM` 是动态路线第一主线。
- 不再把 `MobileNet` 这类大量 `1x1 pointwise` 网络直接当作当前 CoralNPU 公开主链最适配方案。

## 7. 当前一句话总结

当前最合理的总路线是：

```text
用 plain-conv 保住未来空间卷积硬件映射，
用 landmark + 融合路线定义静态精度上限，
再用 landmark sequence + GRU/TCN 作为动态手势第一主线，
最后把硬件设计收敛成“空间卷积后端 + 稠密矩阵后端”的双后端体系。
```
