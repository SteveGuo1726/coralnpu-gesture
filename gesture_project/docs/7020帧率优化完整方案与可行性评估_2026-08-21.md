# Zynq-7020 GestureFlow-NPU 帧率优化完整方案与可行性评估

> 本文是项目自研 GestureFlow-NPU 的性能工程方案，不是 Google CoralNPU 官方设计说明。官方参考仓库 `/home/steveguo/coralnpu-gesture/coralnpu` 只读，本文涉及的 RTL 均位于 `gesture_project/innovation_npu/`。

## 1. 当前真实基线

### 1.0 7020 架构边界硬门禁

本项目当前的 Zynq-7020 PL **不包含 CoralNPU 完整标量前端**。7020 的资源和当前已实现的 MAC/BRAM 通路不允许把官方 `scalar frontend + RVV + ROB/retire + VME` 原样加入；任何后续文档、RTL、软件和板测都必须把它们归入“官方只读参考/未来资源充足平台”路线。7020 当前唯一有效主线是：

```text
PS/ARM 生成 layer/frame descriptor + 一次 doorbell
 -> PL descriptor queue / autonomous scheduler
 -> HP0 AXI burst + activation/weight local bank
 -> 复用的 16x4 INT8 MAC tile + INT32 partial sum
 -> requant/ReLU/pool/GAP/FC + done/fault/performance counters
```

PS 只能负责模型切换时的装载、帧缓冲、描述符提交和结果读取；PS 不得逐窗口、逐像素、逐权重驱动卷积。现有 AXI-Lite 寄存器路径只保留为 debug/回退 ABI。任何把当前 7020 自研模块称为“CoralNPU 标量核心”或“官方 CoralNPU RVV”均为错误表述。

### 1.1 已经实板通过的范围

正点原子 Zynq-7020（`XC7Z020CLG400-2`）已经实际运行完整的静态手势模型：

```text
RGB
 -> conv1_a
 -> conv1_b + pool1
 -> conv2_a
 -> conv2_b + pool2
 -> conv3_a
 -> conv3_b + pool3
 -> conv_head_1x1
 -> GAP
 -> FC
 -> class
```

正式模型是 `gesture_project/models/static_cnn_4x4_w125_h112_nomixup_hagrid6_20260811/model_int8.tflite`。模型使用真实的整型量化参数和真实张量，当前整网验收条件为：

```text
FINAL_RESULT = 0x600D600D
head FNV = 0x53C6484E
GAP FNV  = 0xABBC5831
FC FNV   = 0xDDE32561
class    = 0
```

### 1.2 25 MHz 板级周期基线

当前 writer-burst 验证 bitstream 为 `E:\coralnpu_vivado\projects\gestureflow_layer_chain_hp0_7020_v1\logs\gestureflow_layer_chain_hp0_7020_writer_burst.bit`，对应 XSA 为同目录下的 `gestureflow_layer_chain_hp0_7020_writer_burst.xsa`。SHA-256 分别为 `47d42e3169169c8e11121f85c02a55ea8b328d59005112dbfebad413f307f984` 和 `8acd7e41efc72a6d5407e7b2d0cdad35cd9328b1f2806b615afab7c162ee8010`。实现资源为 `34,584 LUT (65.01%)`、`47,742 FF (44.87%)`、`99 BRAM tile`（`91 RAMB36 + 16 RAMB18`）和 `177 DSP48E1 (80.45%)`，25 MHz 路由时序为 `WNS=+0.324 ns`、`WHS=+0.040 ns`，没有 failing endpoint。旧 SHA-verified bit/XSA 仍保留作回退。

完整证明模式会重复执行三次普通卷积以验证融合池化路径，不能作为发布推理路径。writer-burst 发布模式已在新 bitstream 上实板通过，输出为 `FINAL_RESULT = 0x600D600D`，对应各阶段周期如下：

| 阶段 | 实测周期 |
|---|---:|
| `conv1_a` | 300,010 |
| `conv1_b + pool1` | 726,700 |
| `conv2_a` 三个输出块 | 641,950 |
| `conv2_b + pool2` 三个输出块 | 1,210,676 |
| `conv3_a` 五个输出块 | 547,170 |
| `conv3_b + pool3` 五个输出块 | 969,786 |
| `conv_head_1x1` 七个输出块 | 356,233 |
| `GAP + FC` | 4,771 |
| **发布路径合计** | **4,757,296** |

25 MHz 下发布路径为 `190.29184 ms`，只按 PL 周期折算的理论上限为 `5.255 FPS`。相对旧发布 bit 的 `5,316,780 cycles / 4.702 FPS`，总周期下降 `559,484 cycles`、`10.523%`。这不是摄像头端到端帧率；PS 描述符、权重装载、启动和输入采集时间必须单独测量。

本次下降不能全部归因于 writer burst：同一版还包含 RGB 首层从 4 个输入组改为 1 个有效组的确定性修复，首层从 `857,578` 降到 `300,010`，理论节省 `442,368 cycles`。writer burst 已通过 RTL 回归并随新 bit 实板通过，但尚未生成“仅关闭 burst”的同 RTL 对照 bit，因此当前只能报告整版结果，不能报告 writer burst 的独立 FPS 增益。

### 1.3 端到端性能计数

在同一 writer-burst bit/XSA 上，ARM 程序增加了低扰动 `XTime` 计数并再次实板通过。`PROBE[130..133]` 分别为：整帧 `127,122,031` global-timer ticks，输入准备 `439,845` ticks，权重/量化参数 AXI-Lite 装载 `30,581,233` ticks，PL 周期总和 `4,757,340`。按当前约 `333.333 MHz` global timer 折算，整帧约 `381.37 ms`，输入准备约 `1.32 ms`，权重装载约 `91.74 ms`；PL 纯周期仍按 25 MHz 口径为约 `190.29 ms`。两类数字分别描述 PS 端到端观察和 PL 时钟周期，不能混用。

这组数据改变了优化优先级：连续帧每帧重复的权重/量化参数写入已经占据约 `30.58M` global-timer ticks，下一阶段应优先做模型切换时一次装载、跨帧权重驻留和 descriptor/doorbell 自主调度；在当前 `177/220 DSP`、`99/140 BRAM tile` 和放置压力下，不应先复制第二个完整 MAC tile。

## 1.4 主线架构硬门禁

此前版本虽然已经实现了片上权重银行和 INT32 部分和驻留，但软件仍然以“PS 逐个输出 tile 写寄存器、启动一次 layer”为主要调度方式。这只能作为可回退的板级基线，不能作为面向摄像头连续帧的最终软硬件协同架构。后续主线必须同时满足以下条件：

1. **权重生命周期门禁。** 模型未切换时，连续帧不得重新通过 AXI-Lite 写入权重、bias 或 requant 参数；权重必须在模型加载阶段一次进入 PL 本地 bank，或者由 PL 的 AXI master 从 DDR/权重 SRAM 自动搬入本地 bank。硬件需提供权重版本号/指纹、命中计数、实际装载字节数和装载 fault。
2. **控制边界门禁。** PS 不得在每帧逐输出 tile 下发 `WCTRL/WDATA/BIDX/RQ*`，也不得为每个 tile 单独发一次启动。PS 只提交帧描述符或 doorbell；PL 自主完成 tile 顺序、Cout 分块、pool、量化和结束状态。旧寄存器 ABI 保留为 debug/回退模式，不得继续作为发布模式。
3. **CoralNPU 微架构对齐门禁。** 项目自研引擎必须明确借鉴并落地 CoralNPU 的可编程控制前端、向量/矩阵后端解耦、片上寄存器/向量状态驻留、统一存储访问和命令队列思想；不能只把固定卷积外设通过 AXI-Lite 挂在 ARM 旁边后称为 CoralNPU 协同设计。项目自研扩展必须标注为 `PROJECT_LOCAL_SELF_RESEARCH_NOT_GOOGLE_OFFICIAL`，不能冒充上游 RTL。
4. **数据流门禁。** 输入行缓存、权重 tile、局部部分和和量化输出必须采用可证明的驻留/复用策略；每层必须记录 DDR 读写字节、AXI burst 数、MAC 空闲周期、片上命中率和中间张量写回次数。只报告 MAC/cycle 而不报告数据搬运和 PS 开销，不能作为性能结论。
5. **连续帧门禁。** 以真实摄像头输入为最终场景，至少验证连续两帧和连续多帧：权重装载次数应为一次，帧间不能发生旧权重污染，输入/输出 ping-pong 和 reset/doorbell 状态必须可重复。端到端 FPS 以采集、输入 DMA、PL 推理、结果读取的完整墙钟时间为准；纯 PL 周期只能作为分项指标。
6. **创新性门禁。** “增加 MAC 数量、使用长 burst、加入行缓存、使用 INT8”本身不构成项目创新。主线创新必须落在资源受限 7020 上可实际证明的跨帧权重驻留、PL 自主 tile/层调度、层间局部数据直通、可配置数据流与性能模型闭环；任何声称突破业界的结论必须给出同硬件、同模型、同精度和同输入的可复现实测对照。

当前 `PROBE[132]` 已实测表明每帧重复权重/量化参数写入约 `30,581,233` global-timer ticks，因此下一版若没有“权重未重装 + 命中计数增加 + 连续帧最终 FNV 全部通过”的证据，不得标记为主线性能升级。

### 1.5 新增硬性要求：权重路径必须从架构起点设计

用户已经明确指出：不能先做一个“ARM 逐 tile 写权重”的外设，再在性能暴露后补救搬运路径。今后的硬件、软件、模型和论文表述必须把以下约束作为设计输入，而不是优化建议：

1. **权重不进入每帧关键路径。** 训练导出阶段同时生成模型版本、每个输出 tile 的布局、字节数、DDR 对齐地址、校验值和量化元数据；运行时模型不变时，PS 不能通过 `WCTRL/WDATA/BIDX/RQ*` 重发权重。单纯减少一次重复函数调用不算完成。
2. **PL 负责搬运和调度。** 目标接口是 `descriptor -> doorbell -> PL AXI burst -> local weight bank -> MAC`。权重读取必须与计算解耦，支持至少两个 tile 缓冲或等价的预取机制；计算 tile N 时应能隐藏 tile N+1 的 DDR 读取延迟。AXI-Lite 只保留旧 ABI 回退和故障定位用途。
3. **驻留必须可证明。** 寄存器或性能表必须给出模型版本/权重 key、命中/未命中、实际权重写字节、AXI 读 burst 数、bias/requant 写字节和 fault。不能只根据 RTL 有一个 BRAM 数组就称为权重驻留，更不能用理论带宽替代实测计数。
4. **资源预算优先于堆阵列。** 当前 7020 已使用 `177/220 DSP`、`99/140 BRAM tile`，因此不以复制第二个完整 MAC tile 作为默认方案。优先使用 descriptor 调度、BRAM 权重双缓冲、行/窗口复用、层间局部接力和 16x4 阵列时间复用；任何新增存储或 DMA 必须给出 BRAM、LUT、FF、DSP 和 WNS 预算。
5. **发布验收必须是连续帧。** 至少用同一模型连续两帧：第一帧允许 cold miss，第二帧必须权重写入为零或只发生必要的 tile cache miss，最终张量 FNV、分类、状态 fault 和输入/输出缓冲结果全部一致。报告必须分开给出 PL 周期、PS 控制时间、权重搬运时间和摄像头端到端 FPS。
6. **创新表述必须有实质内容。** “加长 burst、增加 MAC、加行缓存、INT8”只能是工程手段，不能单独作为论文创新。项目要形成的核心贡献是面向 7020 资源边界的可编程 tile 描述符、跨帧权重生命周期管理、计算/权重预取重叠、跨层局部数据接力以及由真实模型计数闭环驱动的数据流选择；必须与当前 PS 逐 tile 基线用同模型、同量化、同输入做 A/B。

## 2. 瓶颈判断

### 2.1 已确认的确定性浪费

自研顶层 `gesture_project/innovation_npu/rtl/gestureflow_layer_chain_hp0_axil.sv` 过去对所有非 40/80 通道模式都给出 4 个输入组。RGB 首层只有 3 个有效输入通道，第四 lane 已经用 `input_lane_enable=4'b0111` 屏蔽，因此只需要一个四通道组。旧设置实际完成了 4 倍的输入通道组调度，浪费量可以精确计算：

```text
(4 - 1) 组 × 16 个 4×4 tap × 9,216 个空间窗口
= 442,368 个周期
```

已将该参数修正为：RGB=`1` 组、16 通道 body=`4` 组、40 通道=`10` 组、80 通道=`20` 组。修复后的理论合计为：

```text
5,316,780 - 442,368 = 4,874,412 cycles
4,874,412 / 25 MHz = 194.976 ms
25 MHz / 4,874,412 = 5.129 FPS
```

以上是周期模型，不是最终实测承诺，必须由新 bitstream 的 `PROBE` 和最终 FNV 共同确认。

### 2.2 计算通路的结构性问题

`gesture_project/innovation_npu/rtl/gestureflow_conv4x4_cin_same_stream.sv` 当前一次只接收、锁存和计算一个 4×4 窗口；`window_ready` 要等 MAC、结果寄存器和输出握手全部空闲。因此窗口之间存在气泡，虽然 MAC 内部已经使用多级流水，但窗口级没有双缓冲。

当前 16×4 tile 每次处理 4 个输入通道、16 个输出通道，并在片上保留 INT32 累加。它不是简单的 ARM 逐窗口外设，但目前空间并行度仍为 1 个窗口/次调度。直接复制第二个完整 tile 的理论收益接近 2 倍，然而当前已经使用 `177/220` 个 DSP，第二个 16×4 tile 至少还需要约 64 个 DSP，不能在当前 7020 资源和时序预算内直接加入。

### 2.3 DDR/控制通路问题

`gesture_project/innovation_npu/rtl/gestureflow_hp0_tensor_loader.sv` 当前使用大 packed FIFO，每消费一个向量就整体右移 `CHANNELS*8` 位；在 80 通道模式下这是 640 位移位网络。它还禁止 AXI 接收与像素消费同周期进行，造成至少一个供给气泡。

`gesture_project/innovation_npu/rtl/gestureflow_hp0_tensor_writer.sv` 原来对每个输出向量单独发 `AW -> W(1/2 beat) -> B`，层间写回大量受 AXI 地址和 B 通道往返影响。当前已增加项目自研的受限连续 burst：仅对非池化、16-byte 连续向量启用最多 4-vector/8-beat burst；40/80/112 通道跨像素 tile、pool 和尾块仍按原路径写，防止破坏 NHWC 布局。该优化已通过普通、stride/tail、pool 和 4 KB 边界回归，但尚未有新 bit 的实板 cycle 数据，不能宣称帧率收益。

### 2.4 时序问题

当前 25 MHz 只有 `+0.140 ns` setup 裕量和 `+0.011 ns` hold 裕量，不能先把时钟改为 50 MHz。重点风险包括 packed 动态索引、大 FIFO shift、量化乘法/移位、FNV 调试哈希和 writer 地址控制。任何优化都必须先保持 25 MHz 正确性，再单独做 50 MHz OOC 与整系统实现。

## 3. 优化目标和评价方法

优化目标不是只追求一个漂亮的周期数字，而是同时满足：

1. 最终 q27/q28/q29、类别和 DMA fault 与当前 golden 完全一致。
2. 25 MHz 先稳定达到 `>=5 FPS` 的 PL 周期上限，再争取 `8~12 FPS`。
3. 不超过 7020 的保守预算：LUT `<70%`、DSP `<90%`、BRAM `<80%`，并保留实现时序裕量。
4. 每个版本记录每层周期、总周期、AXI 读写字节、AXI burst 数、MAC 空闲周期、LUT/FF/BRAM/DSP、WNS/WHS、最终 FNV 和实板结果。
5. 对摄像头场景另行记录端到端 FPS：采集、ROI/缩放、缓存、推理和结果输出不能混入纯 PL FPS。

## 4. 分阶段路线

### 阶段 A：已经落地的低风险收益

- 删除完整证明模式中的重复普通 `conv1_b`、`conv2_b`、`conv3_b` 回放；`GF_FAST_RELEASE=1` 已默认打开，`GF_FAST_RELEASE=0` 仍保留完整证明回归。
- 修正 RGB 首层输入组为 1，保留第四 lane 的零点/权重屏蔽语义。
- 修复 `gestureflow_conv4x4_cin_stream.sv` 的 32 位参数到 16 位端口的显式转换，使独立 Verilator 回归不再被既有宽度警告中止。
- 已通过通道流、MAC tile、pool writer、真实 GAP/FC RTL 回归；快速发布软件已经重新编译；旧 bit 上快速发布整网也已经实板 PASS。

### 阶段 B：不改变模型和接口的供数/写回优化

第一项 RTL 优化应是 banked ring FIFO，替代 `gestureflow_hp0_tensor_loader.sv` 的整体右移：

- 以 64 位 beat 为基本单元，使用读写指针和 beat 数计数。
- loader 允许“同周期消费一个完整向量并接收一个 AXI beat”，用组合的入队/出队计数避免旧的互斥条件。
- 保留 4 KB 边界切分、最大 16 beat burst、输入像素原子性和 `RRESP/RLAST/RID` 检查。
- 对 16/40/80 通道分别验证 burst 边界、backpressure、尾部和错误响应。

第二项是 writer 小型 FIFO 和连续向量突发：

- 先在相邻且连续的输出向量上合并 4~8 个 64 位 beat。
- pool/tail 情况继续保留 `WSTRB`，不能为了长突发破坏 40/80/112 通道 NHWC 布局。
- 已实现并通过 4-vector burst 的 RTL 定向验证；当前仍需以完整 Vivado implementation 和实板每层 cycle、AXI burst 数对比确认收益，不能把事务数量减少直接等价为帧率线性提升。
- 读 bank、组装 W data、AW 和 B response 分别寄存，避免把动态地址和 packed bank 数据放进一个组合路径。

这两项主要减少供数空泡和 AXI 事务开销，不能假定会按 DDR 字节减少比例线性提速；必须通过每层周期和 burst 计数证明收益。

### 阶段 C：权重驻留和命令描述符

当前每个输出 tile 都由 ARM 通过 AXI-Lite 重复写入大量 `WCTRL/WDATA/BIDX/RQ*`。对于连续摄像头帧，权重不会变化，最优做法是：

1. 上电或模型切换时装载一次权重和量化参数。
2. 增加 `FRAME_START`/`JOB_DESC` 寄存器组，描述输入地址、输出地址、宽高、Cin/Cout、stride、pool、权重基址和 lane mask。
3. PL 内部执行 tile 描述符，PS 只写 doorbell 并等待完成。
4. 使用两个 activation buffer 做 ping-pong，下一层读取上一层输出时避免 ARM memcpy。
5. 用 AXI HP0 传输权重或预装 BRAM；不让 PS 每帧逐项写权重。

这一阶段是从“PS 控制的加速器”转向“PL 自主执行的手势推理引擎”的关键，预计对连续帧的端到端 FPS 收益大于单纯提高 MAC 时钟。必须先保留当前寄存器接口作为兼容模式，新增 descriptor 模式作为 A/B 分支。

**当前已落地到 RTL 的第一步。** `gestureflow_layer_chain_hp0_axil.sv` 现已包含一个固定 4-entry descriptor staging bank 和 `LOAD/START/WAIT` 调度状态机。单次 `DESC_CONTROL.doorbell` 可让 PL 顺序重放最多四条已经预装权重的 layer/tile descriptor；每条 descriptor 只能在真实 `store_done` 或 `post_done` 后推进下一条。两任务真实顶层 Verilator 回归已通过，证明 PS 不需要为第二条任务再次写 `CONTROL.start`。这只是配置/任务调度第一步：bias/requant 元数据和权重 tile 的 PL DMA 自动装载尚未并入 descriptor，不能把它写成跨帧完整模型权重驻留已经完成。

### 阶段 D：片上层间接力

优先选择 `conv3_b + pool3 -> head1x1 -> GAP`，原因是空间尺寸已降到 `24×24` 和 `12×12`，片上缓冲需求明显小于前端：

- conv3_b 输出 80 通道，先按 16 通道 tile 分块。
- pool3 只保留 2×2 窗口所需的局部行数据。
- head1x1 直接消费 pool3 的 INT8 输出，不把完整 pool3 tensor 写回 DDR。
- head 输出直接进入已有 GAP/FC 的片上累加接口。
- 先保留 conv3_b 的 DDR 输出作为回退开关，再比较 DDR 字节和周期。

7020 当前 BRAM 余量不足以盲目保存多个完整大 tensor，必须采用行驻留、通道 tile 驻留和小型 ping-pong FIFO，而不是复制完整 feature map。该路径若正确，可减少后两层中间 tensor 的 DDR 往返，但需要增加跨模块握手和更严格的 reset/尾块处理。

### 阶段 E：模型-硬件联合选择

当前 4×4 模型是唯一已经整网实板通过的主线，不能直接替换。已知 3×3 RepVGG 候选 `gesture_project/models/repvgg_3x3_i96_hagrid6_tuned_20260731/deploy/model_int8.tflite` 的卷积 MAC 为 `172,523,520`，比当前 4×4 模型的 `217,165,824` 少约 `20.56%`，但它需要新的 3×3 window mode、权重布局和逐层 golden 验证。

因此模型分支按以下顺序评估：

- 4×4 主线：优先完成阶段 B/C/D，保证可复现和实时化。
- 3×3 候选：独立增加 `KERNEL_SIZE=3` 参数化窗口，完成 float、full INT8、RTL、实板四级验证后再比较。
- 混合 3×3+1×1：只在通道数、BRAM tile 和 requant 规则能映射到现有 tile 时采用，不能仅凭 FLOPs 宣称收益。
- 输入分辨率/ROI：先用固定摄像头 ROI 做 `96×96`、`80×80` A/B，必须保持独立人物测试集精度和全 INT8 精度达标。

模型选择的最终指标是：独立测试准确率、全整型量化准确率、完整 TFLite 输出一致性、7020 实板周期、DDR 字节和端到端 FPS；不是 MAC 数量单项最小。

## 5. 创新点的落地边界

可形成项目创新的不是把论文名词堆进 RTL，而是将它们在 7020 资源约束下落成可测结构：

- 借鉴 Eyeriss row-stationary：三行/四行窗口和局部部分和驻留，当前已有窗口缓存和片上 INT32 累加，后续扩展到层间行接力。
- 借鉴 NVDLA/VTA 的 descriptor 思路：把 PS 逐寄存器控制改成可回放的层描述符和 doorbell。
- 借鉴 Eyeriss v2 的可重构数据流：不是复制多套阵列，而是在一个 16×4 tile 上选择输入驻留、权重驻留和输出驻留的调度模式。
- 面向手势视频的专用创新：权重跨帧永久驻留，输入/输出行缓冲和后层 GAP 流水跨帧复用；这比单帧一次性卷积更直接对应摄像头应用。

目前尚未实现的内容不得写成已实现：多 outstanding AXI、长 burst writer、片上跨层接力、稀疏零跳过、动态 tile 重组、50 MHz 时序和摄像头 AXI-Stream 均属于后续阶段。

## 6. 验证闸门和操作纪律

每个 RTL 版本必须按以下顺序通过：

1. 30 秒内 Verilator 单模块回归。
2. 30 秒内真实模型单层/后处理回归。
3. 有界软件编译。
4. Vivado 复制源码到 `E:\coralnpu_vivado` 的本地工程后构建；不要让 Vivado 直接使用 `\\wsl.localhost\...` UNC 源码路径。
5. 重新记录综合、布局布线、bitgen 资源和时序。
6. 实板下载同一时间戳的 bit/XSA/ELF，检查 `FINAL_RESULT`、各层 cycles、FNV 和 fault。

任何超过约 3 分钟的命令都必须使用 `timeout`，并保留日志路径；不能用“还在运行”代替结果。Windows 侧工具为 `E:\Xilinx\Vivado\2023.2` 和 `E:\Xilinx\Vitis\2023.2`，板测前需要 Windows `hw_server` 监听 `tcp:127.0.0.1:3334`。`cmd.exe` 从 WSL 启动时会显示 UNC 当前目录警告，脚本必须随后 `pushd E:`，不能让 XSCT source UNC 路径。

## 7. 结论

7020 上当前最现实的跨越式路线是“减少无效工作 + 让数据流连续 + 让 PL 自主调度 + 后层片上接力”，而不是在当前资源和时序状态下盲目增加 MAC 阵列。首层分组修复已经给出确定的约 `8.3%` 总周期收益上限，发布模式已经给出约 `1.60×` 相对证明路径的收益；后续若阶段 B/C/D 均通过，才有依据争取从 `4.7 FPS` 进入更高帧率区间。所有更高的数字必须来自真实 7020 bitstream 和整网板测。
