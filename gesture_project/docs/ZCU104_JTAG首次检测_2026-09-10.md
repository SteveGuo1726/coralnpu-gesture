# ZCU104 JTAG 首次检测记录（2026-09-10）

## 1. 本次目标

确认 ZCU104 板卡、USB-JTAG 连接和 Vivado 2023.2 工具链是否正常。

本次只做只读 JTAG 检测，不烧 bitstream，不改变板卡启动介质。

## 2. 官方资料

- AMD ZCU104 Evaluation Board User Guide（UG1267）：
  <https://docs.amd.com/v/u/en-US/ug1267-zcu104-eval-bd>
- AMD Vivado Programming and Debugging（UG908）：
  <https://docs.amd.com/r/en-US/ug908-vivado-programming-debugging>
- AMD Vitis Embedded Software Development（UG1400）：
  <https://docs.amd.com/r/en-US/ug1400-vitis-embedded>

UG1267 说明 ZCU104 的电源、启动模式、USB-JTAG/UART 和板载外设；UG908 说明
Hardware Manager、hw_server、JTAG chain 和 device programming 的标准流程。

## 3. 实际连接

Windows 设备管理器识别到：

```text
FriendlyName     : USB Serial Converter
BusReportedDesc  : JTAG+3Serial
InstanceId       : USB\VID_0403&PID_6011\26588
```

这是 ZCU104 板载 FT4232H 的 `JTAG + 3 UART` 复合设备。

Vivado Hardware Manager 识别到：

```text
ZCU104_JTAG_INVENTORY_TARGET=localhost:3121/xilinx_tcf/Xilinx/26588A
ZCU104_JTAG_INVENTORY_DEVICE=xczu7_0
ZCU104_JTAG_INVENTORY_IDCODE=00010100011100110000000010010011
ZCU104_JTAG_INVENTORY_PART=xczu7
ZCU104_JTAG_INVENTORY_REGISTER.IR=000001010001
ZCU104_JTAG_INVENTORY_DEVICE=arm_dap_1
ZCU104_JTAG_INVENTORY_IDCODE=01011011101000000000010001110111
ZCU104_JTAG_INVENTORY_PART=arm_dap
```

转换为十六进制：

| 器件 | IDCODE |
|---|---|
| Zynq UltraScale+ PL TAP (`xczu7_0`) | `0x14730093` |
| ARM DAP (`arm_dap_1`) | `0x5BA00477` |

## 4. 测试含义

以下链路全部通过：

1. USB 线、板载 FT4232H JTAG 通道正常；
2. hw_server 能启动并监听 `localhost:3121`；
3. Vivado Hardware Manager 能打开 JTAG target；
4. PL TAP 可见，`xczu7_0` IDCODE 可读；
5. PS ARM DAP 可见，`arm_dap_1` IDCODE 可读。

这证明“JTAG 下载/调试链路”是通的。它还不等同于“PL 逻辑已在运行”，因为本次
没有烧写 bitstream，也没有加载 PS ELF。

设计内容：

1. 使用 ZCU104 板载 300 MHz 差分系统时钟；
2. 通过 `IBUFDS` 进入全局时钟；
3. 28-bit 计数器自由运行；
4. `counter[27:24]` 驱动 4 个用户 LED。

实测构建和烧写结果：


```text

```

说明：bitstream 已成功下载，Vivado 报告 startup 状态为 HIGH。板上 4 个用户 LED
应持续闪烁；如果 LED 不闪，下一步应检查板卡电源、LED 参考电平 `VADJ`、以及
UG1267 中 GPIO LED 的物理位置。

如果后续要跑 GestureFlow-NPU，还需要把现有 Zynq-7020 设计迁移到 Zynq UltraScale+
MPSoC：AXI HP 端口、PS 配置、DDR 地址映射和 Vitis 平台都要重新生成。
