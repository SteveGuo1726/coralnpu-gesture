# GestureFlow-NPU 总体定位与论文级路线

## 1. 已确定的定位

GestureFlow-NPU 是项目自研、面向 ZYNQ-7020 实时 RGB 手势识别的**可编程专用 NPU**。它参考 Google CoralNPU 的“控制与加速解耦、片上复用、局部累加、量化执行”思想，但不是 CoralNPU 官方实现，也不修改只读的 `coralnpu/`。

第一版不实现通用 RISC-V 指令集。ZYNQ PS 的 ARM 负责摄像头帧管理、DDR 分配、模型装载和描述符下发；PL 接收有限而可扩展的层描述符，独立完成规则卷积。原因是手势模型以固定形状的 INT8 卷积、池化和归约为主，完整通用处理器的取指、寄存器堆、异常和通用访存会占用 7020 中本应留给 MAC、BRAM、DMA 和摄像头的资源。后续若动态手势的时序层需要不规则操作，可在 PS/RVV 软件侧完成，或增加极小的描述符控制器；不得为了“通用”把重型标量核重新塞回 PL。

## 2. 首版可验证创新

首篇论文应聚焦一个可测、可复现的组合，而不是同时宣称二十三项创新：

1. **行驻留与输出驻留混合数据流**：K 行滚动窗口保留空间复用；16 个输出通道权重 bank 同时读取；一个输出 tile 的跨输入通道 INT32 部分和留在本地，直至完成全部 `Cin` 组。
2. **卷积后处理融合**：在同一数据流中完成 bias、逐通道整型重定标、ReLU 和 2x2 池化，仅将最终 INT8 输出写回片上输出缓冲或 DDR。
3. **手势网络层描述符调度**：由 PS 一次下发整层/条带任务，而非每窗口写寄存器。描述符包含张量地址、H/W/C、kernel、stride、padding、输出通道 tile、量化参数地址、融合标志和双缓冲索引。
4. **模型驱动的设计空间评估**：使用真实 18 类模型的层形状、量化参数和实测零值率，比较固定 16x4、可选 8x8/4x16 模式的资源、DDR 字节、周期与准确率，而非以假设百分比下结论。

## 3. 已验证事实与边界

- `16x4` INT8 tile 在 XC7Z020 上真实综合为 64 DSP48E1、16 RAMB18E1、4089 LUT、3329 FF，100MHz WNS 为 +1.722ns。
- 4x4 行缓存、RGB 首层、跨输入通道组 (`Cin=8`) 均已 Verilator 对账通过；`Cin=16/32/48` 采用同一接口，但尚未使用真实模型权重逐点验证。
- 当前数据流不能称为动态脉动阵列、稀疏加速器、近似计算或多模态 NPU；这些均尚未实现。

## 4. 对候选方向的取舍

立即实施：行驻留、输出驻留、量化融合、描述符驱动、真实模型性能建模。

条件实施：PE 静态重组仅当真实层形状表明 16x4 利用率不足时加入；零值跳过仅当量化后权重/激活稀疏率和节省周期超过索引、门控和负载不均衡成本时加入。

暂不进入首版：近似乘法、DVFS、存算一体、Transformer 注意力、光流、联邦学习、神经形态、多模态深度/IMU。这些会分散验证资源，且当前摄像头 RGB 静态主线没有数据与硬件闭环支撑。

## 5. 下一步验收顺序

1. 恢复训练后导出最佳模型，完成独立 Float/INT8 测试。
2. 导出每层真实 INT8 权重、bias、输入输出零点、逐通道 multiplier/shift 和逐层真值。
3. 将真实 `Cin=16/32/48` 层接入跨组 wrapper，逐点验证本地 INT32 累加。
4. 加入精确重定标、ReLU 和池化并逐点对账。
5. 接 AXI-Lite 描述符与 HP-DDR DMA，整层批处理后再接 OV5640 摄像头。
6. 每版报告 FPGA 资源、实现后 WNS、DDR 字节、周期、帧延迟、功耗和最终 INT8 准确率。
