统一使用：

如果外网依赖需要走代理，记得同时显式导出：

```bash

export HTTPS_PROXY=http://127.0.0.1:7897
```

## 7. Coral 官方风格的正确理解

当前已经补看了 Coral 官方网页，以及本地 `coralnpu/doc/` 文档。

官方网页参考：

- `https://developers.google.com/coral/guides/software/prerequisites`
- `https://developers.google.com/coral/guides/software/simulator`
- `https://developers.google.com/coral/guides/software/bare-metal-prog`
- `https://developers.google.com/coral/guides/software/run-mobilenet`
- `https://developers.google.com/coral/guides/hardware/evaluation`
- `https://developers.google.com/coral/guides/hardware/integration`

本地官方文档：

- `coralnpu/doc/overview.md`
- `coralnpu/doc/simulation.md`
- `coralnpu/doc/integration_guide.md`
- `coralnpu/doc/tutorials/writing_coralnpu_programs.md`
- `coralnpu/doc/tutorials/npusim_mobilenet_tutorial.md`

从这些文档与当前已跑通链路，可以抽出四条正式原则：

### 7.1 先走 prerequisites 和仿真链，再谈 SoC/板级

顺序应是：

```text
prerequisites / build
-> cocotb / npusim / elf
-> official integration style
-> host load / execute / readback
-> 板级闭环
```

这和当前项目从 official replay、再收口到 rowhandoff CSR/readback 的路线是一致的。

### 7.2 主机侧操作必须有最小启动顺序

根据官方 integration guide 与 bare-metal 页面，最小 host 启动顺序应包括：

1. 初始化 ITCM
2. 设置 `PC_START`
3. 释放时钟门控
4. 释放 reset
5. 轮询 `STATUS` 的 `HALTED / FAULT`

并且官方明确建议优先用 `.elf` 而不是 `.bin` 做这一条链，因为 `.elf` 更适合装载和调试。

### 7.3 外部 CSR 地址不要再用旧口径

当前 rowhandoff 板级 sideband CSR 地址应使用：

```text
0x0820 ~ 0x083c
```

不要再沿用旧的：

```text
0x0800 ~ 0x081c
```

因为官方 `CoreAxiCSR` 已占用其中一部分调试 CSR。

### 7.4 不要试图一次性“全复刻最终最优版”

官方流程强调先做最小可验证执行链。对我们来说，对应的正确做法是：

- 先做 `mode=1` 的板级近似语义
- 先跑最小 CSR / trace / host readback 闭环
- 先保证 correctness 和对账
- 之后再谈更深收益
