# ZCU104 上板前审查与修订方案（2026-09-11）

> 本文是「先取证、再动手」的产物。在跑任何重型 Vivado 操作之前，
> 先把 **官方例程**、**本机已跑通的工程**、**本工程的 RTL 与软件** 三方面证据摊开，
> 逐条对照，找出真正的偏差与上板风险。

---

## 0. 一句话结论

**移植方向没错，但流程偏离了官方与 7020 母本太多。**
真正的偏差集中在 4 件事：**① 自定义 RTL 的集成方式（我自创了 Module Reference，应回到打包 IP）；
② 从口选错（HPC0 应为 HP0）；③ Wrapper 注册方式（手工搬运，应托管）；
④ 工程生命周期（每次从零重建，应做持久模板）。**
RTL 本身与软件本身经审查**没有上板阻塞项**。

官方 000035309 的完整步骤（原文核对）：
1. Create Project → **Boards 页选 `Zynq UltraScale+ ZCU104 Evaluation Board`**
2. Settings → **IP → Repository → 加入自定义 IP 的 `ip_repo`** ← *打包 IP*
3. Create Block Design → Add IP：**自定义 IP + Zynq UltraScale+ MPSoC**
4. **Run Block Automation**（勾 Apply Board Preset）
5. 配置 MPSoC：
   - PS-PL → Master Interface：**取消勾选 AXI HPM1 FPD**（只留一个主口）
   - PS-PL → Slave Interface AXI HP：**勾选 AXI HP0 FPD**
6. **Run Connection Automation**（跑两次）——Vivado 自动连 AXI 与时钟/复位
7. Address Editor：控制口 **`0xA000_0000`**
8. **Validate Design**
9. **Create HDL Wrapper → "Let Vivado manage wrapper and auto-update"**
10. **Generate Block Design → Generate Bitstream**
11. **Export Hardware（勾 Include bitstream）→ XSA**
12. Vitis：platform from XSA → app → 处理器 **`psu_cortexa53_0`** → standalone → **Empty Application (C)**

## 3. 已确证的技术事实（可直接作为后续依据）

### 3.1 ZCU104 板卡预置到底设了什么（`preset.xml` 原文提取）

| 参数 | 值 | 含义 |
|---|---|---|
| `PSU__FPGA_PL0_ENABLE` | `1` | PL0 时钟**默认已开** |
| `PSU__CRL_APB__PL0_REF_CTRL__FREQMHZ` | `100` | **PL0 默认 100MHz**，源 `IOPLL` |
| `PSU__CRL_APB__PL0_REF_CTRL__SRCSEL` | `IOPLL` | 阶段 1 提频就改这里 |
| `PSU__USE__M_AXI_GP0` | `1` | HPM0 开 |
| `PSU__USE__M_AXI_GP1` | `1` | **HPM1 也被预置打开**（41-2670 警告的来源） |
| `PSU__USE__S_AXI_GP*` | **完全不存在** | 预置**不管** PL→PS 从口，必须显式开 |
| DDR4 | SODIMM / 64bit / 1067MHz / `PSU__DISPLAYPORT__ENABLE=1` 等 | **全部是 PS 专用引脚，不占 fabric** |

> 推论：**ZCU104 的 BD wrapper 没有端口是正确的**。
> 7020 的 wrapper 有 `DDR_addr/DDR_ba/...` 是因为 Zynq-7000 的 DDR 走 fabric；
> ZynqMP 的 DDR/固定 IO 是 PS 专用引脚，不需要 fabric 端口。

### 3.2 `realtime/tmp` 清理失败 —— 机制已查明，根因尚未根治

- `.Xil/<host>/realtime/` 是 Vivado 存放 **OOC 黑盒 stub（`*_stub.v`）** 的目录，
  属 **hierarchical OOC 综合的正常机制**。
- **成功的 7020 综合日志里 `realtime` 出现 10 次**，`.Xil` 目录在成功后被保留
  （含 `system_wrapper_propImpl.xdc`），并正常产出 `.dcp` 与 `__synthesis_is_complete__`。
- 7020 母本用**默认 hierarchical + 打包 IP + `launch_runs`**，为
  `system_gestureflow_0_30` / `system_axi_smc_26` / `system_processing_system7_0_0`
  各自建了 OOC run，**全部 0 error**。
- 结论：**「打包 IP + hierarchical + launch_runs」在 7020 上是成立的**。
  我此前"自打包 IP 就是根因"的判断**不成立** —— 那只是现象相关，不是因果。

### 3.3 关键顺序（本机已跑通脚本给出）

```
add_files → set_property top <top> → update_compile_order → launch_runs impl_1 -to_step write_bitstream
```
**`set_property top` 必须在 `update_compile_order` 之前**。
反了的话（我原脚本就是这样），`update_compile_order` 会在 top 未定时把
够不到的源文件全部标 `AutoDisabled=1` 并**持久化进 `.xpr`**，
综合随即报 `[Synth 8-439] module 'system_wrapper' not found`。
（现场证据：`.xpr` 里 21 个 RTL 中 16 个 + BD + wrapper 全被标了 `AutoDisabled`。）

### 3.4 其余已核实的小坑

| 项 | 结论 |
|---|---|
| ZynqMP 从口使能属性 | 实测 `PSU__USE__S_AXI_GP0 → S_AXI_HPC0_FPD`；`GP1 → S_AXI_HPC1_FPD`。**HP0 的属性名待一次探针证实** |
| `set_property CONFIG.X` 对不存在的属性 | **不报错**（静默忽略）→ 必须 dump 实际引脚验证，不能凭"设成功"判断 |
| 从口地址段路径 | `/zynq_ultra_ps_ps_e_0/SAXIGP0/HPC0_DDR_LOW`（非 `.../S_AXI_HPC0_FPD/...`） |
| `proc_sys_reset` 的 `C_EXT_RESET_HIGH` | v5.0 **只读**（实测=1），而 `pl_resetn0` 低有效 → 已插反相器 |
| Windows 路径长度 | 260 上限真实存在（第一次失败有它的份）→ 继续用短路径 `C:\vivado_zcu104\gfz` |
| Module Reference 硬限制 | 只接受 Verilog/VHDL 顶层，**不接受 SystemVerilog**（`[filemgmt 56-195]`）→ 这是我为它写 `.v` 封装的原因 |

## 4. RTL 与软件审查结论

### 4.1 RTL（`innovation_npu/rtl/`，构建用 21 个文件 ≈ 5,700 行）

| 检查项 | 结果 |
|---|---|
| 21 个文件是否覆盖全部被实例化模块 | ✅ **`UNRESOLVED` 为空**（严格集合差集验证） |
| 与 7020 母本源列表是否一致 | ✅ **逐字一致（21/21）** |
| 时钟域 | ✅ **单时钟域**，全部 `posedge aclk` + `aresetn`；内部**无 PLL/MMCM** |
| 顶层端口 | 60 个（2 时钟/复位 + 19 `s_axi_*` + 39 `m_axi_*`） |
| 我写的 `.v` 封装端口对应 | ✅ 逐一对应，参数透传完整 |
| AXI-Lite 从口实现 | ✅ 标准 1 拍响应（`aw_seen`/`w_seen`→`bvalid`/`rvalid`），无突发 |
| 标识 | `MAGIC = 0x47464E50`（"GFNP"）、`VERSION = 0x00050001` |
| **`aclk` 的 `FREQ_HZ`** | ⚠️ **RTL 里硬编码 `80000000`** —— 这才是"80MHz FREQ_HZ"问题的真正来源 |
| `s_axi_*` 的 `X_INTERFACE_INFO` | ⚠️ **没有**（只有 `m_axi_*` 有）→ 依赖打包时按端口名推断 AXI4-Lite（7020 已验证可行） |

### 4.2 软件（`gestureflow_hagrid18_dmp_main.c`，712 行）

| 检查项 | 结果 |
|---|---|
| PS 专用寄存器依赖 | ✅ **无 SLCR / devcfg / GIC / PS7 专有寄存器** |
| 仅用通用 API | ✅ `Xil_In32/Out32`、`Xil_DCacheFlushRange`、`XTime_GetTime`、`xil_printf`、`usleep` |
| `XTime` 时钟源 | ✅ 走 BSP 的 `COUNTS_PER_SECOND`，**无硬编码 tick** |
| `GF_BASE` / `PROBE_BASE` | ✅ 已加 `#ifndef` 守卫，ZCU104 侧用 `-DGF_BASE=0xA0000000U` 覆盖，**7020 语义字节不变** |
| **`PROBE_BASE = 0xFFFF0000` 在 ZynqMP 是否合法** | ✅ 合法 —— UG1085：ZynqMP OCM = `0xFFFC_0000–0xFFFF_FFFF`，四个 64KB bank，**OCM3 = `0xFFFF_0000`**。裸机（无 ATF）可自由使用 |
| `FINAL_RESULT=0x600D600D` 谁写的 | ✅ **软件写的**（`probe[index]=value`，`PROBE_BASE` 是 PS 侧指针）→ **NPU 只写 DDR** |
| 因此 NPU `M_AXI` 的地址映射 | ✅ 只需映射 DDR —— 与 7020 母本 `HP0_DDR_LOWOCM = 0x0–0x3FFFFFFF` **一致** |
| ⚠️ 待确认 | ZynqMP `HP0` 是**非相干**口（同 7020 的 `S_AXI_HP0`）。软件启动前有 `Xil_DCacheFlushRange`；**结果回读前是否 invalidate 需复核**（软件侧小改，非阻塞） |

## 5. 上板风险清单与处置

| # | 风险 | 严重度 | 处置 |
|---|---|---|---|
| R1 | 从口用了 **HPC0（相干）**，而 7020 与官方都是 **HP0（非相干）**；缓存一致性语义不同 | **高** | 改 `S_AXI_HP0_FPD`；属性名先用一次 60 秒探针证实 |
| R2 | RTL 硬编码 `FREQ_HZ 80000000`，与 PL0=100MHz 不符 | 中 | **PL0 设 100MHz**（IOPLL 整数分频，精确可达）**+ 打包时覆盖 FREQ_HZ=100MHz**；RTL 不动（保 7020 语义） |
| R3 | 每次 `rm -rf` 从零建工程 → wrapper / BD 内部 IP 注册异常 | **高** | 改**持久模板工程**：BD 与工程建一次、存盘，后续只 `open_project` 改 BD |
| R4 | Wrapper 手工搬运 | 中 | 改官方托管式（`make_wrapper -import`），并在 `set_property top` 之后才 `update_compile_order` |
| R5 | BD 内部 IP（含 SmartConnect 这个**嵌套 BD**）生成文件未进工程 | 中 | 由 `launch_runs` 流程处理（会话内 `synth_design` 永远不解析它们，已实测） |
| R6 | `realtime/tmp` 清理失败（确定性复现过） | **高** | **未根治**。本次严格复现 7020 条件（持久工程 + 打包 IP + hierarchical + `launch_runs`）；若复现则按「同类现象」针对性处理，不再乱改流程 |
| R7 | HPM1 悬空警告 41-2670 | 低 | `PSU__USE__M_AXI_GP1 {0}`（与官方一致） |
| R8 | Windows 260 字符路径 | 低 | 继续短路径 `C:\vivado_zcu104\gfz` |

## 6. 修订后的执行计划（分步、每步可验证、不再盲跑）

### P0 — 前置取证（**唯一需要跑 Vivado 的轻量动作，约 60 秒**）
建一个临时工程 → 加 `zynq_ultra_ps_e` → 应用板卡预置 →
设 `PSU__USE__S_AXI_GP2 {1}`（及备选属性名）→ **dump 实际接口引脚**，
确认 **HP0 的正确属性名**。**不做综合、不做实现。**

### P1 — 建持久 ZCU104 模板工程（一次，产物留盘）
- project part `xczu7ev-ffvc1156-2-e`，board `xilinx.com:zcu104:part0:1.1`
- BD `system`：MPSoC（板卡预置）+ 关 `M_AXI_GP1` + 开 **HP0** + SmartConnect×2 + `proc_sys_reset`
- PL0 = **100MHz**；控制口 `0xA0000000`；NPU 主口 → `HP0_DDR_LOW`
- `validate_bd_design` → `save_bd_design` → **存盘关闭**
- **验收**：模板工程在盘上可独立打开，BD 无 ERROR/CRITICAL

### P2 — 打包 GestureFlow IP（对齐 7020 母本）
- `ipx::package_project` → `ip_repo`
- **在打包阶段把 `aclk` 的 `FREQ_HZ` 钉成 `100000000`，并设 `value_resolve_type user`**
- **验收**：`component.xml` 里 FREQ_HZ=100000000 且可解析

### P3 — 在模板上集成并出 bitstream
- `open_project` 模板 → 删旧 `gestureflow_0` → 加新 cell → 参数按已验证配置
  （`MAX_INPUT_CHANNELS 48 / OUT_LANES 16 / POOL_BANK_ADDR_W 12 / ENABLE_WIDE_MODES 1 /
  `ENABLE_POSTPROCESS 1 / ENABLE_RELAY 0 / ENABLE_STREAM_STORE 0`）
- `create_bd_cell -type ip -vlnv ...` → 连 AXI/时钟/复位 → 地址 → `validate` → `save` → `generate_target`
- **托管式 wrapper** → `set_property top` → `update_compile_order`
- `launch_runs impl_1 -to_step write_bitstream -jobs 8`
- **验收**：bit + XSA + 资源/时序报告（首个 ZCU104 真实 WNS）

### P4 — 软件
- XSA → Vitis 平台（`psu_cortexa53_0`，standalone）→ Empty App + 本工程 `main.c`
- 编译参数 `-DGF_BASE=0xA0000000U`
- **验收**：ELF 生成

### P5 — 上板
- XSCT：`fpga -file <bit>` → `dow <elf>` → `con`
- 读 `FINAL_RESULT`，应 `0x600D600D`；逐层 FNV 与 TFLite golden 一致
- **验收**：`0x600D600D` + FNV 位精确

## 7. 需要拍板的 4 件事

1. **是否同意把集成方式改回「打包 IP + 持久模板工程」**（即 7020 母本模式，也是官方模式）？
