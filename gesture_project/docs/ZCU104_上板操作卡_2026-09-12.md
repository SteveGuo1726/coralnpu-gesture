## ⚠️ 先读这段：写卡前必须先"校验镜像"

**校验命令**：

```bash
cd ~/coralnpu-gesture/gesture_project/innovation_npu/board_zcu104/plnx
bash 05_verify_image.sh        # 末行必须是 RESULT: PASS
```

它不需要 root，用 `debugfs` 从 `rootfs.ext4` 里把二进制 dump 出来，
与仓库源码做**字符串双向比对**，证明"卡上跑的就是这份代码"。

万一不 PASS：

```bash
bash 06_install_app.sh   # 投放源码 → do_cleanall → 全量重编 → 再次校验
```

> **注意一个反直觉点**：有些源码里的诊断文案**不会**出现在二进制里，
> 因为它们的守卫条件是编译期常量（编译器做死代码消除后连带删掉了字符串）。
> 例如 `gf_npu.c` 里 `bytes_needed > GF_BUF_SIZE`（578 KB > 16 MiB，恒假）
> 那句 `Widen the reserved-memory node` 就搜不到 —— **这是正常的**。
> 校验脚本已经避开这类字符串，只用依赖"运行时数据"的探针。
> 同理，`do_compile` 的日志恒为 ~85 字节也正常（gcc 成功时无输出）。

## ★ 迭代期不要拔卡：串口直接覆盖二进制（2026-09-12 新增）

改一行驱动就重写 431 MB 的 rootfs、再拔插一次 SD 卡 ≈ 15 分钟一轮，其中绝大部分是
重复劳动。板子已经在跑 Linux、根文件系统可写，所以**只把那一个二进制送过去**即可：

```bash
cd ~/coralnpu-gesture/gesture_project/innovation_npu/board_zcu104/plnx
TTY=/dev/ttyUSB1 bash 10_push_app.sh          # 或 probe / camera 只推一个
```

它做四件事，全部带校验：

1. `debugfs` 从 `rootfs.ext4` 取出刚编好的二进制（**不需要 root**）；
2. 先跑 `05_verify_image.sh`，**不 PASS 就拒绝推送**（避免把上一版推上去）；
3. `09_board_put.sh` 走串口：base64 → 板上 `python3` 解码 → **两侧 md5 + 长度双向核对**；
4. 板上 `install` 到 `/usr/bin`，再回读 md5 与本地对账。

**量级**：526 KB ≈ 1 分钟，实测 **11.3 KiB/s**（正好 115200 线速，无损）。

> **只有这四样东西必须回到写卡**：设备树、内核、`boot.scr`、`BOOT.BIN` —— 它们在启动
> 分区 / FIT 里，串口覆盖不了。以及最终**固化一版完整镜像**交差时。
> **⚠️ 别把"板上跑通了"和"镜像里有这一版"当成同一件事**：`10_push_app.sh` 只改板上那份，
> 要让镜像也带上，仍须 `06_install_app.sh` + `04_make_sd.sh`。

## 第 1 步：确认镜像没问题（不用板子，先在 WSL 里看）

```bash
cd ~/coralnpu-gesture/gesture_project/innovation_npu/board_zcu104/plnx
bash 05_verify_image.sh
```

**判据：末行必须是 `RESULT: PASS`。** 重点看四段：

| 段 | 看什么 |
|---|---|
| `[3] 二进制属性` | 是 `ARM aarch64`；`gf_camera` 链到 libjpeg |
| `[4] 内容比对` | 17 条探针应全部 `OK`（二进制里的字符串能在源码里逐字找到）|
| `[5] 反向一致性` | 源码文案在镜像里的命中率 ≥ 50% |
| **`[7] 设备树 ↔ 驱动常量`** | **5 条全 OK**：memory 覆盖 0x70000000 / 无 `no-map` / DT 节点地址长度 == `gf_npu.h` / `gf_npu.c` 带 `O_SYNC` / `image.ub` 内嵌 DTB == `system.dtb`。<br>**任意一条不过都别上板** —— 板上表现为**没有内核日志的 SIGBUS**，极难定位（见 `PITFALLS.md #14/#15`）|



## 第 2 步：写 SD 卡（需要 sudo，插上读卡器）

```bash
# 先找出卡的设备名 —— 认准 SIZE 与 RM=1（可移动）
lsblk -o NAME,SIZE,RM,TYPE,MOUNTPOINT,MODEL

# 把 /dev/sdX 换成上面看到的（整盘，不是分区，不要带数字）
sudo bash ~/coralnpu-gesture/gesture_project/innovation_npu/board_zcu104/plnx/04_make_sd.sh /dev/sdX
```

> **⚠️ 已修掉的坑**（PITFALLS #11）：`sudo` 把 `$HOME` 变成 `/root`，脚本原先用
> `$HOME` 找工程树，会报 `missing /root/gf_linux_ws/...` —— 镜像其实就在。现在四个
> 脚本都会自动解析调用者的家目录。若仍有偏差：`sudo GF_HOME=/home/steveguo bash <脚本>`。

脚本会：先**自动跑 `05_verify_image.sh`**（不 PASS 直接拒绝）→ 校验 manifest 含 `gf-npu`
→ 让你把设备名再手打一遍确认 → 分区（p1 FAT32 1 GiB / p2 ext4 剩余）→ 写 rootfs
→ **`resize2fs` 撑满分区** → 只读挂载复核文件存在、打印 `file` 结果、打印 md5。

**判据**：复核结果里 4 个文件都是 `OK`，`gf_camera` 显示 `ARM aarch64`，
且两个二进制的 md5 与第 1 步 `[6] 指纹` 段**完全一致**。

## 第 3 步：上电

1. 卡片插到 **J100**（ZCU104 的 SD 卡座）
2. **SW6 [4:1] = OFF, OFF, OFF, ON**（SD1）
   - ⚠️ 极性：**ON = 0，OFF = 1**。出厂默认是 QSPI32，必须改。
3. 串口：板载 USB-UART 是 FT4232H 的 **channel 0**，**115200 8N1**
   - Windows 上会枚举成 `COMx`（去设备管理器看哪个口对应 channel 0）
   - 或 WSL 里用 `screen /dev/ttyUSB0 115200`（如果 USB 直通进来了）
4. 上电

## 第 4 步：板上依次执行（**不要跳步**）

### 4.1 确认摄像头被枚举

```bash
lsusb | grep -i -E 'cam|video|logitech|webcam'
ls /dev/video*
```
**判据**：`lsusb` 里有你的摄像头；`/dev/video0` 存在。
**不是** `super-speed` 也能继续（USB2 带宽对 640×480 足够），但记一下。

### 4.2 确认摄像头支持的格式

```bash
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video0 --list-formats-ext
```
**记下**：有哪些 `MJPG` / `YUYV`，支持哪些分辨率。

### 4.3 ★ NPU 自检（**最关键的一步**）

```bash
sudo gf_npu_probe
```

**必须看到 `RESULT: PASS`**，并且逐层内容校验全 `MATCH`：

```
gf_npu: PL id ok (MAGIC 0x47464E50, VERSION 0x00050001)
gf_npu: staged weights + activations, ... of 16 MiB
=== reference-image pass ===
class = 1 (...), expected 1
  per-tile PL cycles: ...
  --- golden content checks (bit-exact memcmp) ---
    conv0  MATCH
    pool1  MATCH
    conv2  MATCH
    pool2  MATCH
    conv4  MATCH
    pool3  MATCH
    6/6 matched
  --- hardware FNV registers ---
    hw FNV conv0   ...  (expect 05307466)
    hw FNV pool1   ...  (expect 7E276C7B = pre-pool conv1 output)
  ...
RESULT: PASS
```

**在看到 PASS 之前，摄像头报出的任何类别都不算数。**

### 4.4 性能对比（V4）

```bash
sudo gf_npu_probe --bench 200
```
**记下** `CPU overhead`，与裸机的 **10.04 ms** 对比。
Linux 侧换了访存方式（普通非缓存 + `memcpy`），这是验证那个改动是否有效的直接证据。

### 4.5 实时摄像头

相机**目前是正装的**（2026-09-12 已物理转正），所以下面**不加 `--rotate`**。

> 若画面上下/左右仍是反的，用 `--rotate 0|90|180|270` 修正 —— **这是运行期参数，
> 改它不需要重编也不需要重写卡**。它之所以存在，是因为这个朝向已经变过一次：
> 一开始相机是倒装的，`--rotate 180` 修好；后来物理转正，参数又回到 0。
> **所以"该不该加"取决于当前物理安装，不要照抄历史命令行。**

```bash
sudo gf_camera -s 640x480          # 默认 /dev/video0，多数投票窗口 5 帧
sudo gf_camera -s 640x480 -n 100   # 只跑 100 帧
sudo gf_camera --list              # 只列格式
sudo gf_camera -s 640x480 -n 50 --save-ppm /tmp/npu_in.ppm   # 存最后一帧（曝光已收敛）

# 若哪天画面反了，就按当前安装角度补上，例如：
# sudo gf_camera -s 640x480 --rotate 180 -n 5 --save-ppm /tmp/chk.ppm
```

### 4.6 浏览器实时监视器（可选，需要网线）

先让网口起来（板子 GbE → 路由器；或网线直连笔记本配静态地址，见
`docs/ZCU104_实时监视器_2026-09-12.md` §2）：

```bash
ip link set eth0 up
udhcpc -i eth0                      # 会打印租到的 IP
```

```bash
sudo gf_camera -s 640x480 --view 8080
```

启动时会自己打印 `http://<板子IP>:8080/`，用笔记本浏览器打开即可。页面上有：
NPU 实际输入、全景、当前类别与票数、耗时分解、18 类分布、**真值标注实测准确率**。

**它不会拖慢识别**（这是设计约束，有测试和实测数字）：没人打开页面时每帧只多两次比较
（37 ns，一帧的 0.0001%）。**所以基准测试请用不带 `--view` 的命令行**，或者按下面三遍对照量一次：

```bash
gf_camera -n 300                                # 基线
gf_camera -n 300 --view 8080                    # 开了但没人看 —— 应与基线一致
# 第三遍：开着 --view 并用浏览器打开页面、勾选全景，看增量
```

## 故障排查表

| 症状 | 最可能的原因 | 怎么办 |
|---|---|---|
| `gf_npu_probe`: `open /dev/mem failed` | 没用 root / 内核无 `DEVMEM` | 用 `sudo`；`ls -la /dev/mem` 确认存在 |
| `gf_npu` 报 `GF_MAGIC = 0x00000000` 或 `0xFFFFFFFF` | PL 没配置（bitstream 没加载）或 PL 时钟被关 | `cat /proc/device-tree/chosen/bootargs` 看有没有 `clk_ignore_unused`；`dmesg \| grep -i fpga` |
| `GF_VERSION` 不匹配 | bitstream 与驱动不是同一版 | 确认用的是新烧的镜像（BOOT.BIN 里含 `system.bit`） |
| 某层 `*** MISMATCH ***` | 真的有不一致 | 记下打印的**首个差异字节偏移 + 两侧 FNV**，发我 |
| `lsusb` 里没有摄像头 | USB 供电/线缆/格式 | 换线；`dmesg \| tail -30` 看 USB 枚举日志 |
| 有 `/dev/video0` 但没有 `/dev/video1` | 正常（UVC 只有一个节点） | — |
| `gf_camera`: `no usable format at 640x480` | 摄像头不支持这个组合 | 用 `--list` 看支持的组合，改用 `-s 1280x720` 等 |
| `--view` 起来了但浏览器打不开 | 没插网线 / 不同网段 | `ip -br addr` 看板子有没有 IPv4；`ip -br link` 里 `NO-CARRIER` 就是没插线 |
| `viewer: bind port 8080 failed` | 端口被占 | 换个端口 `--view 8081`；这条**不影响流水线**，程序继续跑 |
| 页面第一次显示空白 | 每个流的**第一个**请求按设计返回 503（那次请求就是"登记兴趣"） | 等约 0.5 s，页面的 `onerror` 会自动重试 |
| 板上类别与手势对不上 | 画面方向不对（相机装反/装转，或照抄了旧命令里的 `--rotate`） | 先存一帧 `--save-ppm` 看方向；用 `--rotate 0\|90\|180\|270` 修正，见 4.5 |
| 帧率很低（< 10 fps） | 走的是 YUYV 大分辨率 / CPU 侧开销大 | 换成摄像头支持的最低分辨率；看 4.4 的 CPU overhead |
| SD 启动不了（串口无输出） | SW6 拨错 / 卡没插好 / BOOT.BIN 不对 | 复查 SW6（**ON=0, OFF=1**）、重插卡 |

## 之后可以做的优化（按收益排序）

| 优化 | 依据 | 预期收益 |
|---|---|---|
| **双缓冲流水**：抓帧与 NPU 计算重叠 | 预留段已按 16 MB 留足 | 端到端帧率接近 PL 计算时间的倒数 |
| **PL 提频到 ~137 MHz** | `WNS +2.751 ns @ 100 MHz`，0 失败端点 | PL 17.02 ms → ~12.4 ms |
| **权重装载改 DMA burst**（若仍是逐字写） | 硬门禁：必须分离报告搬运开销 | 板上实测过 114 ms → 预期 1~5 ms 量级 |
| **MJPEG 优先** | recipe 已开 `-DGF_HAVE_JPEG` | 带宽更省，高分辨率下帧率更高 |

> ⚠️ 硬门禁提醒：**任何性能数字都必须分离报告 PL 计算时间与 CPU/搬运开销**，
> 只报 MAC/cycle 不构成性能结论。
