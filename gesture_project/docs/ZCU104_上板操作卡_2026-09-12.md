## 第 2 步：写 SD 卡（需要 sudo，插上读卡器）

```bash
# 先找出卡的设备名 —— 认准 SIZE 与 RM=1（可移动）
lsblk -o NAME,SIZE,RM,TYPE,MOUNTPOINT,MODEL

# 把 /dev/sdX 换成上面看到的（整盘，不是分区，不要带数字）
sudo bash ~/coralnpu-gesture/gesture_project/innovation_npu/board_zcu104/plnx/04_make_sd.sh /dev/sdX
```

脚本会：先校验 manifest 含 `gf-npu`（不含就拒绝烧录）→ 让你把设备名再手打一遍确认 →
分区（p1 FAT32 1 GiB / p2 ext4 剩余）→ 写 rootfs → **`resize2fs` 撑满分区** →
只读挂载复核 `/usr/bin/gf_npu_probe` 等文件存在，并打印 `file` 结果。

**判据**：脚本最后打印的复核结果里 4 个文件都是 `OK`，`gf_camera` 显示 `ARM aarch64`。

---

## 第 3 步：上电

1. 卡片插到 **J100**（ZCU104 的 SD 卡座）
2. **SW6 [4:1] = OFF, OFF, OFF, ON**（SD1）
   - ⚠️ 极性：**ON = 0，OFF = 1**。出厂默认是 QSPI32，必须改。
3. 串口：板载 USB-UART 是 FT4232H 的 **channel 0**，**115200 8N1**
   - Windows 上会枚举成 `COMx`（去设备管理器看哪个口对应 channel 0）
   - 或 WSL 里用 `screen /dev/ttyUSB0 115200`（如果 USB 直通进来了）
4. 上电

## 第 4 步：板上依次执行（**不要跳步**）

### 4.1 确认摄像头被枚举

```bash
lsusb | grep -i -E 'cam|video|logitech|webcam'
ls /dev/video*
```
**判据**：`lsusb` 里有你的摄像头；`/dev/video0` 存在。
**不是** `super-speed` 也能继续（USB2 带宽对 640×480 足够），但记一下。

### 4.2 确认摄像头支持的格式

```bash
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video0 --list-formats-ext
```
**记下**：有哪些 `MJPG` / `YUYV`，支持哪些分辨率。

### 4.3 ★ NPU 自检（**最关键的一步**）

```bash
gf_npu_probe
```

**必须看到 `RESULT: PASS`**，并且逐层内容校验全 `MATCH`：

```
gf_npu: PL id ok (MAGIC 0x47464E50, VERSION 0x00050001)
gf_npu: staged weights + activations, ... of 16 MiB
=== reference-image pass ===
class = 1 (...), expected 1
  per-tile PL cycles: ...
  --- golden content checks (bit-exact memcmp) ---
    conv0  MATCH
    pool1  MATCH
    conv2  MATCH
    pool2  MATCH
    conv4  MATCH
    pool3  MATCH
    6/6 matched
  --- hardware FNV registers ---
    hw FNV conv0   ...  (expect 05307466)
    hw FNV pool1   ...  (expect 7E276C7B = pre-pool conv1 output)
  ...
RESULT: PASS
```

**在看到 PASS 之前，摄像头报出的任何类别都不算数。**

### 4.4 性能对比（V4）

```bash
gf_npu_probe --bench 200
```
**记下** `CPU overhead`，与裸机的 **10.04 ms** 对比。
Linux 侧换了访存方式（普通非缓存 + `memcpy`），这是验证那个改动是否有效的直接证据。

### 4.5 实时摄像头

```bash
gf_camera -s 640x480          # 默认 /dev/video0，多数投票窗口 5 帧
gf_camera -s 640x480 -n 100   # 只跑 100 帧
gf_camera --list              # 只列格式
gf_camera --save-ppm /tmp/in.ppm   # 存一帧送进 NPU 的 96x96 图，便于核对预处理
```

## 故障排查表

| 症状 | 最可能的原因 | 怎么办 |
|---|---|---|
| `gf_npu_probe`: `open /dev/mem failed` | 没用 root / 内核无 `DEVMEM` | 用 `sudo`；`ls -la /dev/mem` 确认存在 |
| `gf_npu` 报 `GF_MAGIC = 0x00000000` 或 `0xFFFFFFFF` | PL 没配置（bitstream 没加载）或 PL 时钟被关 | `cat /proc/device-tree/chosen/bootargs` 看有没有 `clk_ignore_unused`；`dmesg \| grep -i fpga` |
| `GF_VERSION` 不匹配 | bitstream 与驱动不是同一版 | 确认用的是新烧的镜像（BOOT.BIN 里含 `system.bit`） |
| 某层 `*** MISMATCH ***` | 真的有不一致 | 记下打印的**首个差异字节偏移 + 两侧 FNV**，发我 |
| `lsusb` 里没有摄像头 | USB 供电/线缆/格式 | 换线；`dmesg \| tail -30` 看 USB 枚举日志 |
| 有 `/dev/video0` 但没有 `/dev/video1` | 正常（UVC 只有一个节点） | — |
| `gf_camera`: `no usable format at 640x480` | 摄像头不支持这个组合 | 用 `--list` 看支持的组合，改用 `-s 1280x720` 等 |
| 帧率很低（< 10 fps） | 走的是 YUYV 大分辨率 / CPU 侧开销大 | 换成摄像头支持的最低分辨率；看 4.4 的 CPU overhead |
| SD 启动不了（串口无输出） | SW6 拨错 / 卡没插好 / BOOT.BIN 不对 | 复查 SW6（**ON=0, OFF=1**）、重插卡 |

## 之后可以做的优化（按收益排序）

| 优化 | 依据 | 预期收益 |
|---|---|---|
| **双缓冲流水**：抓帧与 NPU 计算重叠 | 预留段已按 16 MB 留足 | 端到端帧率接近 PL 计算时间的倒数 |
| **PL 提频到 ~137 MHz** | `WNS +2.751 ns @ 100 MHz`，0 失败端点 | PL 17.02 ms → ~12.4 ms |
| **权重装载改 DMA burst**（若仍是逐字写） | 硬门禁：必须分离报告搬运开销 | 板上实测过 114 ms → 预期 1~5 ms 量级 |
| **MJPEG 优先** | recipe 已开 `-DGF_HAVE_JPEG` | 带宽更省，高分辨率下帧率更高 |

> ⚠️ 硬门禁提醒：**任何性能数字都必须分离报告 PL 计算时间与 CPU/搬运开销**，
> 只报 MAC/cycle 不构成性能结论。
