# 权重驻留的架构真相 2026-08-26

> 本文纠正一个被文档带偏的关键假设。结论来自实际 RTL 和实际权重数组大小，不是纸面估计。

## 1. 一句话结论

`B1 权重跨帧驻留（消除 91.74ms 装载，2.62→3.42 FPS）` 在当前硬件上**不可能按原设想实现**。原因是 16×4 MAC tile 的权重 SRAM 总共只有约 32KB，而整网权重约 200KB，差约 6.25 倍。这不是软件没做对，是硬件容量从根本上不够。

## 2. 实测容量与需求

权重 bank 结构（来自 `gestureflow_mac_tile.sv` / `gestureflow_weight_bank.sv`）：

```text
每输出 lane：ADDR_W=9 -> 512 项 x 32bit = 2KB
16 输出 lane：16 x 2KB = 32KB
地址 = {weight_bank_select(1bit), tap*16 + ic_group(8bit)}
即：2 个 bank，每个 16KB，总计 32KB
```

实际权重数组大小（来自 `innovation_npu/board_7020/software/*.h`）：

| 层 | 权重字节 |
|---|---:|
| conv1 | 768 |
| body | 4,096 |
| conv2a | 10,240 |
| conv2b | 25,600 |
| conv3a | 51,200 |
| conv3b | 102,400 |
| head1x1 | 143,360（含 16 tap，有效约 8,960） |
| FC | 672 |
| 合计（有效） | 约 203,936 ≈ 200KB |

所以：

- 单 bank（16KB）连最大的 `conv3b`（100KB）都装不下，差约 6 倍。
- 双 bank（32KB）只够装整网权重的约 1/6。
- 跨帧驻留要求整网权重全部常驻，需要约 200KB 权重 SRAM，约等于现在 32KB 的 6.25 倍。

## 3. 当前软件的 fingerprint 驻留为什么是“空转”

`gestureflow_layer_chain_hp0_main.c` 里的 `weight_prepare()/weight_commit()` 已经写了 fingerprint + key/hit/miss。但它有两点使其无法产生收益：

1. 硬件 `weight_resident_key` 只有一个槽位，只能记住**一个** layer/tile 的 key。网络里每个 layer/tile 的 fingerprint 都不同，所以每层必然 miss、必然覆盖前一层。
2. 双 weight bank 没有被软件使用（`weight_bank_select` 未在 `load_*` 里设置）。

因此当前“权重驻留”只是寄存器和指纹计算存在，板测上没有任何一层的权重真正被复用；114ms 装载是 AXI-Lite 逐字写造成的，指纹命中从未发生。

## 4. 纠正后的 B1 策略

原 B1 目标要改写，真正可落地的是两条：

### 4.1 短期：把 AXI-Lite 逐字写换成 PL DMA burst（可行，收益大）

- 硬件已有 `gestureflow_hp0_weight_dma_loader`，可从 DDR 经 HP0 突发读入本地 bank，但板级软件没有用它。
- 当前 114ms 主要是 `conv3a/conv3b`（约 150KB）的 `Xil_Out32(WCTRL/WDATA)` 逐字写。
- 改成权重在 DDR 连续打包 + `WEIGHT_DMA` 突发装载，预计把 114ms 压到 1~5ms 量级（受 DDR 带宽和 bank 乒乓限制）。
- 这是不增加 BRAM、不动 MAC 阵列前提下最直接的板上帧率提升。

### 4.2 中期：把 relay/output bank 省下的 BRAM 还给权重 SRAM

- 当前 `output_bank` 是 `2x16384x128bit`，OOC `RAMB36=224`，严重超配。
- 把 relay 改成 K 行 ring 后，可释放大量 BRAM。
- 用释放的 BRAM 把权重 SRAM 从 32KB 扩到约 200KB（或至少扩到能装下最大的几个高频层），才可能真正做跨帧常驻。

## 5. 直接结论

不要再按“软件打开权重驻留开关就能 2.62→3.42”去改。板上第一优先动作应是：**把权重装载从 AXI-Lite 逐字写切换为 PL DMA 突发装载**，并实测第二帧/第三帧的装载时间是否降到个位数 ms；只有等权重 SRAM 扩容后，才有资格谈“跨帧零重装”。
