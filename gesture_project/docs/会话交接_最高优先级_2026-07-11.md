### 3.4 当前最新硬件判断

当前必须保持清醒的判断如下：

1. `cfg9 + CoreCSR + rowhandoff + WIN3` 这一版已经能在 `7Z010` 上稳定收敛到 `25MHz`。
2. `WIN3` 当前已经不是“只功能打通的 LUT 乘法参考核”，而是真正吃进 `DSP48E1` 的板级稳定版。
3. `DSP_USED` 从之前的 `4` 提升到了 `13`。
   - 原先 `4` 个 DSP 来自 `cfg9` 核内既有乘法路径。
   - 新增 `9` 个 DSP 来自 `gesture_conv3x3_win3_lite.sv` 的 9 路 `8x8` 有符号乘法。
4. 但不要误判成“3x3 后端已经优化完成”。
   - 当前 `WIN3` 仍然只是“单次喂入 3 行 5 列，顺序产出 3 个相邻窗口结果”的窗口级参考核。
   - 它已经具备权重锁存、窗口内输入复用、部分和寄存、DSP 乘法映射。
   - 它还没有做到更完整的连续行缓存、流式输入、跨更多输出通道的真实层加速器形态。
5. 当前已经证明：即使板核里还没加片上 requant 尾部，现有 `WIN3` 也已经能在真板上吃进真实量化层张量，并由 host 侧完成跨 `Cin` 累加后对上 raw conv golden。
   - 这说明“真实模型层数据 -> 板上窗口核 -> host readback 对账”这条主链已经成立。
   - 而且这一条主链已经从“3 个相邻窗口片段”推进到了“单输出通道整行回放”。
   - 现在又进一步推进到了“多输出通道整行回放”，只是当前多输出通道仍由 host 逐通道换权重驱动，不是板上并行 `Cout` 阵列。
   - 板上直接读回的仍然是 raw `int32` 卷积和，这是卷积累加器的正常输出，不代表模型本身存的是 `int32`。
   - 当前已经补齐 host 侧真实量化参数换算，所以现在既能对上 raw `int32`，也能进一步对上 `TFLite` 最终 `int8` 输出。
   - 但仍要注意：requant / output zero-point / fused activation 还没有真正下沉进板上 RTL。
6. `ARM` 板上循环这条线已经从“活跃实验”推进成“已验证可用的加速基线”。

   - 摄像头实时采集
   - PS 端复杂软件栈
   - 完整整网一次性自动调度

### 5.1 Windows Vivado / XSDB 调用规则

- 当前安装的是 Windows 版 `Vivado` / `XSDB`，不是 Linux 版。
- 不要在 WSL 里直接把 Windows 版当 Linux 程序跑。
- 正确调用方式固定为：
  - `cmd.exe /c "cd /d E:\\coralnpu_vivado\\zynqmini_7z010 && call E:\\Xilinx\\Vivado\\2023.2\\bin\\vivado.bat -mode batch -source //wsl.localhost/Ubuntu-22.04/home/steveguo/.../xxx.tcl"`
  - `cmd.exe /c "cd /d E:\\coralnpu_vivado\\zynqmini_7z010 && call E:\\Xilinx\\Vivado\\2023.2\\bin\\xsdb.bat //wsl.localhost/Ubuntu-22.04/home/steveguo/.../xxx.tcl"`
- `cmd.exe` 当前目录不能是 `\\wsl.localhost\...`，必须先 `cd /d E:\...` 到 Windows 本地盘目录。
- 终端里那几行 `UNC` 中文乱码提示可以忽略，只要 `cd /d E:\...` 写对了就行。
- `E:` 盘本地文件尽量直接用 `E:/...` 路径传给 `XSDB`。
  - 特别是 `bit/xsa/elf/bin/ps7_init.tcl` 这类会被 Windows 侧直接打开的文件，优先使用 `E:` 本地路径，不要故意绕成 `//wsl.localhost/.../mnt/e/...`
- 当前 `run_win3_real_layer_fragment.py` 这条 host 保底线仍可继续使用 `//wsl.localhost/...` 形式生成临时 `tcl`。
  - 但 ARM 实验线里，凡是能落到 `E:` 本地的输入文件，优先落到 `E:` 本地，少给 `XSDB` 增加额外路径噪声。

### 5.3 XSDB / 板级调试硬规则

- 当前 `2026-07-13` 晚间已经用真板再次确认：
  - 要让厂家原生 `System Debugger` 最小链稳定跑通，板子必须先处于：
    - `SW1 = JTAG BOOT`
    - 上电后手按一次 `POR / SYS RST`
  - 这一步没做之前，容易复现：
    - `rst -system` 卡 `PLL lock`
    - `dow elf` 报 `DDR controller is held in reset`
- 当前真板最小成功链已经真实打通，口径是：
  - 板卡模式：`JTAG BOOT`
  - 按钮：用 `POR / SYS RST`，不是 `K1/K2/K3`
  - 串口：当前 Windows 上识别到的是 `COM10`
  - 串口速率：`115200`
  - 真板结果：
    - 厂家 `hello world` 已成功下载
    - `A9 #0` 已成功在 `main` 断点停住
    - 放跑后 `COM10` 已真实打印 `Hello World`
- 当前这块板的 `UART` 接法不要再混淆：
  - `UART` 指的是板载 `CH340` 这条串口链
  - 资料确认它连到 `PS UART1 / MIO48 MIO49`
  - 不要把板上的普通 `USB Type-C` 口误当成这一步的 `UART`
- 当前 `Windows` 侧如果只是为了验证最小串口链，建议固定先做：
  - 接 `JTAG`
  - 接 `UART`
  - 切 `JTAG BOOT`
  - 上电
  - 按一次 `POR`
  - 然后再跑 `XSDB`
- 不要并发跑两个 `xsdb` 抢同一块板。
- 看到 `DAP (AHB AP transaction error, DAP status 0x30000021)` 时，不一定要立刻手工重启板子。
- 当前已经验证可恢复流程是：
  - 选 `DAP*`
  - 执行 `rst -system`
  - 等约 `1000ms`
  - 再重新枚举目标
- 当前 `ARM + OCM` 脚本还已经内置了有限自动重试：
  - `gesture_project/board_validation/zynqmini_7z010/current/scripts/host/run_win3_real_layer_fragment_arm.py`
  - 默认 `--xsdb-retries=2`
  - 优先先用脚本自带重试，不要每次第一次遇到 `DAP/AP` 抖动就人工中断整轮回放
- 当前 `cfg9` 板级壳里，核心默认会被 `CoreCSR` 保持在 `reset/cg` 状态。
- 真实板测里必须先处理 `CoreCSR` 控制字：
  - 读 `0x00000000` 会看到 `0x00000003`
  - 再把它清成 `0x00000000`
  - 然后 `DMSTATUS / DATA0` 调试链才会真正通
- 当前从 `Windows xsdb.bat` 跑仓库里的 `tcl` 时，若脚本文件在 `WSL` 路径下，仍然容易踩路径解析坑。
  - 当前实测最稳的做法是：
    - 把本轮要跑的 `tcl` 先复制到 `E:\coralnpu_vivado\vendor_examples\...` 这类 Windows 本地目录
    - 再从 `E:` 本地目录调用 `xsdb.bat script.tcl`
  - 当前这条方法已经真实用于跑通：
    - 厂家 `hello world`
    - 项目侧 `cfg9 gesture win3 smoke`
- 板上对 `0x43C00000` 做寄存器读写时，稳妥方式是：
  - `stop/ps7_init/ps7_post_config` 走 `ARM Cortex-A9 MPCore #0`
  - PL 外设寄存器读写切到 `APU`
  - 显式 `configparams force-mem-accesses 1`

### 5.4 CoreCSR / rowhandoff 当前确认口径

- `0x820 -> {hit, miss, invalidate, produce}`
- `0x830 -> {tail_hit, interior, right_edge, row_last}`
- `0x844 -> state_trace_word`
- `0x840` 是写事件口，不是状态读口
- 当前 `cfg9` 壳里的快捷事件注入口是：
  - `base + 0xB0`
