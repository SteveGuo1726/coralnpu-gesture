# ZYNQ MINI 7Z010 硬件验证状态

## 当前结论

截至 `2026-07-10`，本项目已经完成第一版真实板级硬件闭环：

- Vivado 2023.2 已能识别 Zynq-7000 目标器件 `xc7z010clg400-1`。
- 已生成本项目自有 PS+PL 比特流，文件为 `E:/coralnpu_vivado/zynqmini_7z010/rowhandoff_ps_csr_build/rowhandoff_ps_csr.bit`。
- 已导出硬件平台文件，文件为 `E:/coralnpu_vivado/zynqmini_7z010/rowhandoff_ps_csr_build/rowhandoff_ps_csr.xsa`。
- 已通过 JTAG 将该比特流烧录到开发板 `xc7z010_1`。
- 已通过 XSDB 从 ARM Cortex-A9 调试口读回 PL 侧 AXI-Lite 寄存器，确认 PS 到 PL 的 CSR 通路真实可用。
- 已进一步加入真实 workload 的 111 条 rowhandoff 事件回放，并在板上读回计数结果与离线 trace 重建结果一致。
- 已进一步加入 ARM/host 侧事件注入寄存器，由 XSDB 通过 PS 调试通道向 PL 写入同一组 111 条真实事件，并完成板上计数对账。
- 已进一步完成第一版 ARM 裸机指令流验证：XSDB 只负责下载并启动程序，真正的 `0x43C00040` 事件写入由 Cortex-A9 执行。
- 已进一步完成 ARM 裸机 C 自校验程序验证：用 clang + 本地解包的 `ld.lld-14` 生成 ARM ELF，由 Cortex-A9 执行 C 循环写入 111 条真实事件，自行读回 PL 计数器并将 PASS/FAIL 结果写到 DDR mailbox。

这一步不是最终完整 NPU 上板，但已经不是“只写工具、只跑仿真、只生成 RTL”。它完成的是后续硬件优化必须依赖的板级观测和输入通道：ARM/PS 可以读到 row handoff 计数器和状态寄存器，也可以通过 AXI-Lite 写入 row handoff 事件；其中写事件已经从调试器直接写寄存器推进到 ARM 核执行裸机 C 程序写寄存器，并进一步推进到 ARM 程序自己读计数、自己判断结果。

重要边界更新：`gesture_project/` 中的记录属于项目实验记录，不是 Google 官方要求。当前重新确认后，干净官方 CoralNPU RTL 来自 `coralnpu` 仓库当前 `origin/main`，官方生成物为 `generated_rtl_official/CoreMiniAxi.sv`。项目行移交计数器 `rowhandoff_counter_bank.sv` 是本项目外置扩展，不是 Google 官方 `CoreCSR` 原生功能；旧的 `generated_rtl/CoreMiniAxi.sv` 属于曾经混入项目 rowhandoff 扩展的生成物，后续不能再当作纯官方 RTL 使用。

## 最新推进：真实 workload trace 回放

当前 PS+CSR 外设已经支持两种事件源：

- `control[0] = 1`：启用事件源。
- `control[3] = 0`：使用原确定性调试事件源。
- `control[3] = 1`：使用真实 workload 的 111 条 rowhandoff 事件回放。
- `control[4] = 1`：使用 ARM/host 侧写入的 rowhandoff 事件；该模式优先级高于 trace ROM 回放。

复位默认值为：

```text
CONTROL 0x00000009
```

这表示上电后默认启用真实 trace 回放。trace 来源为：

```text
gesture_project/reports/core_3x3_strategy8_rowhandoff_workload_trace_extracted_2026-06-12.json
```

事件解码遵循项目中已统一的 bit 语义：

```text
bit 0       layer_start
bit 1       hit
bit 2       tail_hit
bit 3       miss
bit 4       invalidate
bit 5       produce
bit 6       interior_row_enter
bit 7       right_edge_done
bit 8       row_out_y_write
bits 21:16  row_out_y
```

本次真实上板流程为：

```text
Vivado 重新构建 bitstream
JTAG 烧录到 xc7z010_1
XSDB 从 ARM Cortex-A9 #0 读 CSR
脚本硬校验 trace 计数
```

XSDB 读回结果：

```text
MAGIC 0x52484F57
VERSION 0x20260710
CONTROL 0x00000009
HIT 0x00000015
MISS 0x00000001
INVALIDATE 0x00000001
PRODUCE 0x00000016
TAIL_HIT 0x00000015
INTERIOR 0x00000016
RIGHT_EDGE 0x00000016
ROW_LAST 0x0000002D
TRACE_REPLAY 0x006FC06E
ROWHANDOFF_WORKLOAD_TRACE_REPLAY_COUNTS_PASS
```

换成十进制即：

```text
hit = 21
miss = 1
invalidate = 1
produce = 22
tail_hit = 21
interior_row_enter = 22
right_edge_done = 22
row_last = 45
trace_event_count = 111
```

这些数值与 `core_3x3_strategy8_rowhandoff_workload_trace_reconstruction_full_2026-06-12.md` 中的离线重建计数一致，说明当前板级硬件已经能回放真实 workload 的 rowhandoff 事件，并由 ARM 侧读回对账。

## 最新推进：ARM/host 侧真实事件注入

在 trace ROM 回放通过后，当前外设继续增加了 host 事件输入寄存器，使 PS/ARM 侧可以通过 AXI-Lite 主动写入事件，而不是只能依赖 PL 内部固定 ROM 自动回放。

新增寄存器：

```text
0x40 host_event_in
0x44 host_event_status
```

host 事件写入仍使用与 trace ROM 完全一致的 bit 语义：

```text
bit 0       layer_start
bit 1       hit
bit 2       tail_hit
bit 3       miss
bit 4       invalidate
bit 5       produce
bit 6       interior_row_enter
bit 7       right_edge_done
bit 8       row_out_y_write
bits 21:16  row_out_y
```

本次板上执行流程为：

```text
Vivado 重新构建 bitstream
JTAG 烧录到 xc7z010_1
XSDB 选择 ARM Cortex-A9 #0
写 control = 0x15 触发软复位并进入 host 注入模式
写 control = 0x11 保持 enable + host 注入模式
向 0x43C00040 写入 111 个真实事件 word
读回计数器和 host_event_status
```

XSDB 读回结果：

```text
CONTROL 0x00000011
HIT 0x00000015
MISS 0x00000001
INVALIDATE 0x00000001
PRODUCE 0x00000016
TAIL_HIT 0x00000015
INTERIOR 0x00000016
RIGHT_EDGE 0x00000016
ROW_LAST 0x0000002D
TRACE_WORD 0x005D6F5C
EVENT_STATUS 0x006F000A
ROWHANDOFF_HOST_INJECT_TRACE_COUNTS_PASS
```

其中 `EVENT_STATUS[31:16] = 0x006F`，即 host 侧实际写入 111 个事件。计数器结果与 trace ROM 回放、离线 row 生命周期重建均一致。

完成 host 注入后，又重新烧录同一 bitstream，让硬件回到默认 `CONTROL = 0x00000009`，并复跑 trace ROM 读回：

```text
CONTROL 0x00000009
HIT 0x00000015
MISS 0x00000001
INVALIDATE 0x00000001
PRODUCE 0x00000016
TAIL_HIT 0x00000015
INTERIOR 0x00000016
RIGHT_EDGE 0x00000016
ROW_LAST 0x0000002D
TRACE_REPLAY 0x006FC06E
ROWHANDOFF_WORKLOAD_TRACE_REPLAY_COUNTS_PASS
ROWHANDOFF_CSR_READBACK_EXISTING_PASS
```

结论：新增 host 注入模式没有破坏默认 trace ROM 回放保底路径。

## 最新推进：ARM 裸机 blob 写事件

由于当前 Windows 侧只有 Vivado/XSDB，没有完整 Vitis；WSL 侧也没有现成 `arm-none-eabi-gcc` 和 `ld.lld`，本阶段没有等待大工具链安装，而是用 clang 内置 ARM 汇编器生成一个极小裸机指令 blob：

```text

gesture_project/board_validation/zynqmini_7z010/xsdb_run_arm_blob_rowhandoff_trace.tcl
```

编译命令：

```text
clang -target armv7-none-eabi -mcpu=cortex-a9 -marm -ffreestanding -c gesture_project/board_validation/zynqmini_7z010/arm_host_inject_rowhandoff_trace.S -o gesture_project/board_validation/zynqmini_7z010/arm_host_inject_rowhandoff_trace.o
llvm-objcopy-14 -O binary -j .text gesture_project/board_validation/zynqmini_7z010/arm_host_inject_rowhandoff_trace.o gesture_project/board_validation/zynqmini_7z010/arm_host_inject_rowhandoff_trace.bin
```


## CSR 地址图

基地址：

```text
0x43C00000
```

HWH 地址范围：

```text
0x43C00000 - 0x43C00FFF
ADDRESSBLOCK RANGE="4096"
```

寄存器表：

```text
0x00 magic
0x04 version
0x08 control
0x0C cycle_count
0x10 hit_count
0x14 miss_count
0x18 invalidate_count
0x1C produce_count
0x20 tail_hit_count
0x24 interior_count
0x28 right_edge_count
0x2C row_last
0x30 state_trace_word
0x34 trace_aux
0x38 row_state
0x3C trace_replay_status
0x40 host_event_in
0x44 host_event_status
```

当前 `control` 复位默认打开 bit0 和 bit3，因此真实 trace 回放默认运行。后续如果需要切回旧的确定性调试事件源，可以写 `0x43C00008 = 0x00000001`；如果需要重新开始 trace 回放，可以写 bit2 触发软复位后保持 `0x00000009`；如果需要 host 注入事件流，可以写 `0x00000015` 触发软复位并进入 host 注入模式，再写 `0x00000011` 保持 enable + host 注入模式。

## 完整 CoreMiniAxi 评估结论

完整 `CoreMiniAxi` 已经可以进入 Vivado 综合，但不适合直接塞进 7Z010 第一版上板：

```text
Slice LUT：44598 / 17600，约 253.40%
Slice Register：8882 / 35200，约 25.23%
BRAM：10 / 60
DSP：6 / 80
100MHz worst setup slack：约 -28.536ns
failing endpoints：约 10152
```

结论：7Z010 上不应强推完整 `CoreMiniAxi` bitstream。正确路线是保留它作为接口和语义参考，先用裁剪后的 PS+CSR 壳把 `RowhandoffCounterBank`、trace 对账和真实 workload 事件输入逐步接进来。

## 下一步

1. 不再回到长仿真作为主要推进方式。短仿真只用于局部 RTL 正确性，板级推进优先使用 Vivado 构建、JTAG 烧录和 CSR 读回。

2. 保持当前 PS+CSR 壳稳定，不随意改地址、时钟、复位和寄存器布局。后续新增字段必须继续通过 XSDB 读回验证。

3. 下一步不再只证明 AXI-Lite 能通，也不再只证明 XSDB 可以直接写寄存器；当前已经完成第一版 ARM 裸机 C 自校验程序。后续应把它升级为 Linux `/dev/mem` 程序或更完整的裸机应用，并把事件来源从内嵌常量表扩展到真实运行时产生或加载。

4. 下一版硬件目标不是完整 NPU 一步到位，而是以干净官方 `CoreMiniAxi` 的接口和调试结构为边界，把项目侧 `RowhandoffCounterBank / CSR readback / trace 对账` 这条可验证路径做实，再逐步扩大到更接近真实执行的装载和运行闭环。

5. 如果后续需要 Linux 用户态读寄存器，可基于当前 XSA 或设备树建立 `/dev/mem` 读回；在此之前，XSDB 已经足够证明 PS 到 PL 的 AXI-Lite 读回通路可用。

## 2026-07-11 7Z010 手势算法专用 3x3 MAC 加速核心

本轮路线做了明确调整：7Z010 版本不再以“完整 Google CoralNPU 上板”为近期目标，而是先做当前手势识别算法的轻量、稳定、可扩展软硬件协同加速版。完整 Google CoralNPU 和资源更大的 NPU 级硬件化，后续留给 7Z020 或资源更充足的平台做对照。

新增硬件模块：

```text
gesture_project/board_validation/zynqmini_7z010/gesture_conv3x3_mac_lite.sv
```

功能：

- 输入 9 个 int8 激活值、9 个 int8 权重和 1 个 int32 bias。
- 执行 3x3 signed int8 dot product。
- 输出 int32 累加结果。
- 输出 ReLU 后 8 位结果。
- 采用三阶段流水/状态机，而不是单拍大组合路径。

新增 AXI-Lite 寄存器区间：

```text
0x100 gesture_mac control
0x104 gesture_mac act0
0x108 gesture_mac act1
0x10C gesture_mac act2
0x110 gesture_mac wgt0
0x114 gesture_mac wgt1
0x118 gesture_mac wgt2
0x11C gesture_mac bias
0x120 gesture_mac status
0x124 gesture_mac int32 result
0x128 gesture_mac relu8 result
0x12C gesture_mac op_count
```

其中 `control[0]` 为手动启动脉冲，`control[1]` 为清除脉冲，`control[2]` 为自动启动使能。自动启动打开后，软件只需要预先写好权重和 bias，再依次写 `act0/act1/act2`；写入 `act2` 后硬件会自动发起一次 3x3 MAC。若写入 `act2` 时核心仍 busy，启动请求会保留到空闲后再执行，避免后续 ARM 侧连续喂数据时丢任务。

设计过程中的关键结论：

- 第一版单拍 9 路并行 MAC 能生成 bitstream，但路由后 setup 时序失败，WNS 约 `-2.505ns`，不能作为稳定上板版本。
- 改为流水/分阶段后，路由后时序满足，说明 7Z010 上应避免把 3x3 乘加和后处理压到单拍大组合路径。

## 2026-07-11 7Z010 双输出滑动窗口 MAC

在单点 3x3 MAC 通过后，本轮继续加入更贴近真实性能优化方向的双输出窗口核心：

```text
gesture_project/board_validation/zynqmini_7z010/gesture_conv3x3_win2_lite.sv
```

该核心一次接收 3 行、每行 4 个 int8 激活值，内部生成两个水平相邻的 3x3 卷积输出：

```text
row0: c0 c1 c2 c3
row1: c0 c1 c2 c3
row2: c0 c1 c2 c3

out0 使用 c0/c1/c2
out1 使用 c1/c2/c3
```

这一步对应的优化意义是：

- 权重和 bias 继续复用 `0x110 - 0x11C` 的驻留寄存器，不为每个输出重复写权重。
- 两个相邻 3x3 输出共享中间两列输入，点 MAC 路径原本需要写 6 个激活寄存器，现在变为写 3 个行窗口寄存器。
- 两个输出的乘法、部分和累加和 ReLU 都在硬件内部完成，中间部分和不落地 DDR。
- 这还不是完整 3 行滚动行缓冲，也还没有实现跨层片内直通；但它已经是后续 row/tile 内核的稳定硬件原型。

新增 AXI-Lite 寄存器区间：

```text
0x140 win2 control
0x144 win2 row0
0x148 win2 row1
0x14C win2 row2
0x150 win2 status
0x154 win2 result0
0x158 win2 result1
0x15C win2 relu8 pack
0x160 win2 output_count
```

其中 `control[0]` 为手动启动脉冲，`control[1]` 为清除脉冲，`control[2]` 为自动启动使能。自动启动打开后，软件写入 `row2` 即触发一次双输出窗口计算；如果核心仍 busy，请求会保留到空闲后执行。
