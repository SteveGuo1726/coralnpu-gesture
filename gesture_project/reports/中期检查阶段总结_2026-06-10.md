## 2. 项目总目标与当前阶段路线重心

结合计划书与当前工程实际，项目总目标可以重述为：

```text
围绕“面向手势识别的 RISC-V + NPU 软硬件协同优化”，
在 CoralNPU 开源体系内建立
算法选择 -> 真实训练/量化 -> NPU 周期画像 -> 软件优化 -> 硬件参考语义 -> 板级最小闭环
这一条可验证的工程路线。
```

中期阶段的路线已经从立项时的“广泛设想”收敛到两条正式主线：

### 2.1 算法主线

- 正式模型主线：
  `static_cnn_regularized_3x3_i96_e70_hagrid6_sample`

这条线的意义是：

- 它不是只靠静态 MAC 估算选出来的。
- 它已经完成 `真实训练 -> INT8 量化 -> TFLite 测试集评估 -> 算子画像 -> NPU 周期估算` 的完整闭环。
- 它在当前正式静态数据上，同时优于现阶段 MobileNetV2 对照的精度和硬件收益画像。

### 2.2 CoralNPU 软件/硬件协同主线

- official `conv.cc` 当前受保护的正式最优主线：
  - `strategy=8`
  - `x4_id32 / x4_id64`
  - `静态主体块调度`
  - `interior 6tap 分带`
  - `顶/底 4/6/4 分带`
  - 四层总 `opt_cycles=17,596,916`
  - `mismatch=0`

- 当前唯一保留的板级硬件参考候选：
  - `rowhandoff_rowbase_recur mode=1`

这两条线的关系必须明确：

- `17,596,916 / mismatch=0` 是当前必须冻结保护的软件保底线。
- `rowhandoff mode=1` 不是新的正式主线，而是“面向上板的第二层硬件参考语义”。

## 3. 对照计划书，中期阶段已经完成的内容

## 3.1 算法与模型侧：已形成正式静态主线，不再停留在设想

计划书里提出了：

- 面向手势识别筛选模型结构
- 做 CNN、轻量模型与时序方案比较
- 做 INT8 量化与部署适配

这部分在当前工作区已经从方向性描述推进到真实闭环。

### 已完成的关键结果

当前正式静态数据集为：

- `gesture_project/datasets/processed/hagrid_sample_static_6cls`

当前正式主线模型为：

- `gesture_project/models/static_cnn_regularized_3x3_i96_e70_hagrid6_sample`

其当前闭环结果为：

- Keras float test accuracy：`77.29%`
- INT8 TFLite test accuracy：`77.07%`
- 量化精度损失：`0.22 pct`
- Conv2D MAC：`89,800,704`
- 模型级估算 reference / optimized cycles：
  `1,130,091,474 / 63,313,051`
- 模型级估算加速：`17.85x`

同时，正式 MobileNetV2 对照也已经完成闭环：

- `mobilenet_v2_a050_96_imagenet_frozen_finetune_hagrid6_sample`
- Keras / INT8：`59.73% / 58.40%`
- 估算加速：`2.62x`
- 主导瓶颈：`conv2d_1x1`

### 当前阶段结论

这部分已经可以比较坚定地汇报为：

```text
项目已经完成了正式静态手势数据上的模型主线筛选，
当前 3x3-heavy CNN 在精度、量化稳定性和 CoralNPU 硬件映射上
都优于本阶段 MobileNetV2 对照，
因此 static_cnn_regularized_3x3_i96_e70_hagrid6_sample
成为当前正式算法主线。
```

这意味着：

- 计划书中“算法要服务硬件映射”的要求，已经不是纸面规划，而是有真实结果支撑。
- 当前阶段不应再把 `CNN-LSTM` 或 `LSTM` 直接当作默认后续主线。

## 3.2 研究现状重审：已把计划书背景信息转化为可执行判断

计划书的“国、内外研究现状和发展动态”并不是无效信息，但必须重审后吸收。

当前已完成三类关键重审：

- `gesture_project/docs/基于大创计划书的阶段重审与路线重规划.md`
- `gesture_project/docs/计划书_国内外研究现状与发展动态重审.md`
- `gesture_project/docs/计划书_算法与技术项逐条重审.md`

中期阶段吸收到的核心结论包括：

1. `HaGRID` 路线支持“先静态、后动态”的分阶段推进方式。
2. `MediaPipe landmarks + 轻分类器/轻时序` 不是旁门，而是后续必须进入正式对照的真实工程路线。
3. `RepVGG / MobileOne` 这类 plain-conv / structural re-parameterization 思路，对当前 3x3 主线有直接参考价值。
4. 动态手势值得做，但 `LSTM` 不能再被默认视作硬件优先主线。

这说明项目没有“偏离计划书”，而是把计划书中原本较粗的背景判断，转化成了更符合当前 CoralNPU 工程事实的路线选择。

## 3.3 CoralNPU 软件优化侧：已经形成稳定 official current best

计划书中关于“提升卷积相关核心计算效率、围绕手势模型热点做 NPU 优化”的目标，当前已经在 official 软件侧形成稳定成果。

当前 official current best 四个核心层结果为：

| 层名 | ref_cycles | opt_cycles | mismatch | speedup |
| --- | ---: | ---: | ---: | ---: |
| `conv2_3x3_a` | 138,812,960 | 5,732,506 | 0 | 24.21506 |
| `conv2_3x3_b` | 240,941,500 | 4,617,766 | 0 | 52.17707 |
| `conv3_3x3_a` | 117,597,531 | 2,440,498 | 0 | 48.18587 |
| `conv3_3x3_b` | 220,314,354 | 4,806,146 | 0 | 45.84013 |

总结果：

- 总 `opt_cycles = 17,596,916`
- 总 `ref_cycles = 717,666,345`
- `mismatch_count = 0`

这条线已经明确回答了计划书中的一个关键问题：

```text
在不改 RTL 的前提下，CoralNPU 官方 conv.cc 软件侧已经能够对
3x3-heavy 手势主线模型的核心层提供很强的加速基础。
```

同时，中期阶段也已经明确排除了多条失败方向，包括：

- `3x3 repack`
- `3x3 postprocess 软件融合`
- `边界行中带块调度`
- `边界点 32/64 窄特化`

这意味着当前 current best 不是“碰巧跑出来”，而是经过系统试错收敛后的稳定保底线。

## 3.4 板级/硬件侧：第一层保底线已完成，第二层已形成可参考语义样本

计划书中的硬件目标包含：

- 面向 3x3 卷积做更高效的并行与数据复用
- 最终走向板级验证

当前中期阶段需要如实分成两层来汇报。

### 第一层：已经完成的最小硬件闭环

这条线已经被真实打通：

```text
core self-write rowhandoff event
-> CoreAxi local bridge
-> RowhandoffCounterBank
-> CSR readback
```

这部分不是文档假设，而是已经有 smoke test 和集成接线清单支撑。

可以汇报为：

- `CoreCSR/CoreAxiCSR` sideband CSR decode 已落地
- `RowhandoffCounterBank` 已落地为正式 Chisel 模块
- `counter bank -> CSR readback` 已完成最小验证

这条线的意义是：

- 当前项目已经不再是“只有软件 patch，没有硬件落点”。
- 已经具备了板级 trace/counter 可观测的基础框架。

### 第二层：已经形成硬件参考候选，但尚未完成完整收口

当前唯一保留的第二层硬件参考候选是：

- `rowhandoff_rowbase_recur mode=1`

这条线之所以被保留，不是因为它已经上板完成，
而是因为它在 official replay 上曾给出过最像“真实硬件语义”的正样本：

- 相对同骨架 `emptyhooks`
  - `conv2_3x3_a = -38,639`
  - `conv2_3x3_b = -9,205`

这说明：

- 相对于许多已经判死的细粒度 patch 变体，
  `rowhandoff mode=1` 是当前唯一还值得继续向板级语义抽象的候选。

更重要的是，当前第二层已经不只是“想法成立”，而是做出了真实 reachability 与生命周期证据。

已完成的 probe 结果表明，在 `mode1_backhalf` 场景下，真实 conv workload 已逐级走到：

```text
out_y = 24: miss + produce
out_y = 25: hit + tail_hit
gate exit row: invalidate
```

最强单条证据为 `backhalf_invalidate_probe`：

- `probe_halt_cycles = 8430912`
- `hit = 21`
- `miss = 1`
- `invalidate = 1`
- `produce = 22`
- `tail_hit = 21`
- `interior_row_enter = 22`
- `right_edge_done = 22`
- `row_out_y_last = 46`

这条结果说明：

```text
rowhandoff 的最小生命周期语义
已经在真实 workload + official counter bank + CSR readback 这条链路上被证实。
```

## 4. 当前还没有完成的内容

为了服务中期检查，必须明确区分“已经做成”和“还没做成”。

### 4.1 尚未完成完整板级主线收口

目前还不能声称：

- 已经完成最终可上板的正式硬件修改主线
- 已经完成完整 workload 的 formal 收口
- 已经完成 FPGA 端到端部署验证

当前最准确的表述应是：

```text
项目已经完成了板级最小观测链路和第二层 rowhandoff 生命周期样本验证，
但“正式完整 workload 的最终停机与全量 counters 收口”仍在最后推进中，
因此还不能把当前状态夸大成“已经完成上板版本”。
```

### 4.2 动态手势路线尚未进入正式实测闭环

当前还没有完成：

- landmarks / skeleton 路线的正式训练与量化对照
- `GRU / TCN / LSTM` 的动态序列 microbenchmark
- 动态路线在 CoralNPU 上的热点映射与硬件价值排序

因此，计划书中关于动态手势和 `LSTM` 的部分，
目前仍处于“路线已重审，但工程闭环尚未开始”的阶段。

### 4.3 FPGA 最终展示仍缺关键一跳

距最终可汇报的上板展示，还差至少三件事：

1. 把 `rowhandoff mode=1` 从“软件参考语义 + CSR counter”继续收缩成更接近 RTL 的稳定状态机表达。
2. 在 `conv2_3x3_b / conv3_3x3_b` 两个关键层上形成最小可对账的板级验证闭环。
3. 完成软件、NPUSim、CSR 计数、RTL 行为之间的统一对账口径。

## 6. 下一阶段计划

后续不应再回到大量偏门微变体扫描，
而应严格按“上板导向”推进。

### 6.1 继续冻结 current best 软件保底线

- 不破坏 `conv.cc` 当前最优主线
- 所有新试验仅在 worktree 和专用 target 中推进

### 6.2 把 `rowhandoff mode=1` 继续收缩成最小板级参考实现

重点不再是继续扫很多 residue/terminal 变体，
而是：

- 明确 `row_enter_event / row_terminal_done / out_y_q` 这组三类控制脉冲
- 抽象出更接近 RTL 的 row-state 递推语义
- 优先围绕 `conv2_3x3_b / conv3_3x3_b` 两层做最小闭环

### 6.3 正式启动动态对照路线，但不抢占静态主线资源

建议下一阶段新增但不替换当前主线的内容包括：

- `MediaPipe landmarks + MLP/TCN/GRU` 的正式对照
- 动态序列 microbenchmark
- 判断 `GRU / TCN / LSTM` 是否值得进入后续硬件阶段

### 6.4 以“可中期汇报、可后续上板”为目标整理材料

需要持续维护的正式材料包括：

- 模型精度与量化闭环报告
- official replay / NPUSim / cocotb 证据链
- rowhandoff CSR 接线、计数器、目标层对账表
- 上板导向的最小验证清单
